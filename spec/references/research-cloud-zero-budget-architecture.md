## 1. Введение и контекст

В ходе исследования современных подходов к агентным средам (анализ проекта **TS Rust**, изолятов V8 в Cloudflare Workers, **Just Bash** от Vercel Labs и платформы **Lakebed** от Theo Browne) было сформировано новое видение развертывания «Секретаря v2».

### Ключевой инсайт:
Традиционные облачные среды для агентов (E2B, Modal, виртуальные машины AWS/Hetzner за $10–40/мес) тратят до 90% стоимости на **простой CPU** во время ожидания генерации токенов LLM. В то же время запуск изолированных агентов в легковесных V8 Isolates (Cloudflare) или эфемерных MicroVM (Firecracker) позволяет свести стоимость простоя к **$0 / месяц**, а стоимость выполнения реальной кодовой задачи — к **долям цента ($0.002)**.

## 2. Разделение системы: «Мозг» против «Рук»

Ключевой архитектурный принцип: **жесткое разделение координатора и исполнителей**.

```
┌─────────────────────────────────────────────────────────────┐
│                 МОЗГ (Secretary Core)                       │
│  - Память, привычки, история диалога, планирование         │
│  - Встроенный SQLite / Durable Objects                      │
│  - Доступность 24/7 с телефона / Telegram / Web            │
│  - Стоимость в простое: $0.00                               │
└──────────────────────────────┬──────────────────────────────┘
                               │
               Защищенный WebSocket (JSON-RPC / ACP)
                               │
         ┌─────────────────────┴─────────────────────┐
         ▼                                           ▼
┌─────────────────────────────────┐   ┌─────────────────────────────────┐
│     РУКИ: Локальная Нода        │   │    РУКИ: On-Demand MicroVM      │
│  - Запущена на ноутбуке / ПК    │   │  - Эфемерный Firecracker Linux  │
│  - Бинарник secretary-node (Go) │   │  - Поднимается за 150мс         │
│  - Доступ к локальному диску    │   │  - Выполняет git/build за 90с   │
│  - Локальные подписки Claude/CX │   │  - Самоуничтожается ($0.002)    │
└─────────────────────────────────┘   └─────────────────────────────────┘
```

1. **`secretaryd` (Мозг / Core):**
   * Ему не нужны гигабайты RAM и Linux-ядро.
   * Он хранит историю, состояние задач, диету, тренировки и заметки.
   * Идеальная среда: **Cloudflare Durable Objects** (или легковесный Go-демон на домашнем сервере).
2. **`secretary-node` (Руки / Runner):**
   * Управляет файловой системой, реальным bash, git, PTY-терминалами и протоколом ACP.
   * Написан на **Go** (статический бинарник ~15 МБ, потребляет 10–20 МБ RAM, моментальный запуск).
   * Запускается либо на личном компьютере пользователя, либо внутри одноразовой MicroVM в облаке.

## 3. Три топологии развертывания (User Topologies)

В спецификацию закладываются 3 взаимозаменяемых режима:

| Топология | Где крутится Core | Где крутятся Nodes | Сценарий использования | Стоимость |
| :--- | :--- | :--- | :--- | :--- |
| **A. Local-First (Power Dev)** | Локально на ноутбуке (Go) | Локально на той же машине | Разработчик работает за своим ПК, максимальная приватность | **$0 / мес** |
| **B. Hybrid Nomad (Баланс)** | В облаке (Cloudflare DO / TS) | На ноутбуке / домашнем сервере | Номад: частые поездки; доступ с телефона; тяжелые задачи на ПК | **$0** простой + подписки |
| **C. Pocket Studio (Zero-Hardware)** | В облаке (Cloudflare DO) | **On-Demand MicroVM** (Firecracker) | Пользователь без личного ПК (только смартфон), старт с нуля | **~$0.05 / день** |

## 4. Разрешение «Дилеммы подписок» (Subscriptions vs. API Keys)

### Проблема:
* Сырые API-токены (Anthropic / OpenAI API) при активной агентной разработке обходятся в сотни долларов в месяц ($50–$500+).
* Большинство разработчиков уже имеют фиксированные подписки по $20/мес: **Claude Pro / Claude Code CLI**, **ChatGPT Plus / Codex**, субсидированные квоты Google.
* Напрямую вызывать подписки из облачного воркера запрещено политиками провайдеров (блокировка по IP / сессиям).

### Архитектурное решение (Reverse Inference Gateway):
1. **Когда ноутбук пользователя онлайн (Крышка открыта):**
   * Облачный Секретарь шлет задачу через WebSocket на локальную ноду `secretary-node`.
   * Нода вызывает локальный CLI (`claude` / `codex`), авторизованный под личной подпиской пользователя.
   * **Результат: $0 за токены**, используется безлимитная/высокая квота подписки.
2. **Когда ноутбук закрыт / пользователь с телефона:**
   * В MicroVM передается зашифрованный сессионный токен подписки (`CLAUDE_CODE_TOKEN` / OAuth refresh token).
   * Так как MicroVM — это полноценный Linux, внутри нее запускается официальный `claude` CLI от имени подписки.
   * После пуша PR контейнер уничтожается, не оставляя следов токена на диске.

## 5. Долговечность состояния в облаке (Durable State & Alternatives)

Для надежной работы агента в Cloudflare Durable Object (выживание при эвикции, перезагрузках, будильниках):

### 5.1. Pi Durable (`@earendil-works/pi-durable`)
* Фреймворк от Армина Ронахера и Марио Цехнера.
* Реализует паттерн **Effect Sandwich**:
  1. Запись намерения вызова инструмента в SQLite.
  2. Выполнение действия.
  3. Запись результата.
* Гарантирует защиту от двойного выполнения опасных побочных эффектов при крашах.

### 5.2. Альтернативы Pi Durable

1. **`@cloudflare/agents` (Официальный Cloudflare Agents SDK):**
   * Нативный класс `Agent` на базе Durable Objects и Vercel AI SDK.
   * Встроенная поддержка SQLite, WebSockets и очередей событий без сторонних зависимостей.
2. **Temporal (Temporal Go / TypeScript SDK):**
   * Золотой стандарт Durable Execution. Поддерживает детерминированные воркфлоу на Go и TS.
   * Идеален для корпоративных развертываний, но требует выделенного сервера Temporal.
3. **Restate (`restate.dev`):**
   * Легковесный движок устойчивого исполнения (написан на Rust, клиенты на TS и Go).
   * Дает Durable RPC и Exactly-Once семантику для распределенных воркеров.
4. **LangGraph (LangChain Checkpointers):**
   * Графовая модель состояний с поддержкой Time Travel и SQLite/Postgres чекпоинтов.
5. **Собственный Event Sourcing на чистом SQLite (Минималистичный путь):**
   * Таблица `agent_steps (task_id, step_num, action, result, status)`.
   * Дает 90% надежности Pi Durable всего за ~50 строк кода без сторонних библиотек.

## 6. Разделение типов данных (Storage Matrix)

| Тип данных | Примеры | Где хранится | Как обрабатывается | Затраты |
| :--- | :--- | :--- | :--- | :--- |
| **Память и знания (Knowledge)** | Диета, тренировки, заметки, Obsidian Vault | Git-репозиторий + кэш в Durable SQLite | Чтение через GitHub REST API / SQLite в V8 (0ms) | **$0.00** (MicroVM не нужна!) |

| **Код проектов (Project Code)** | Репозитории, `node_modules`, бинарники | Git Remote + Cloudflare R2 (S3) | Клонируется в MicroVM или на ноутбук при запуске задачи | **$0.002 / запуск** |

## 7. Роль и выбор языков (Language Architecture)

* **Secretary Core (Облако): TypeScript**  
  Родной язык для V8 Isolates, Cloudflare Workers, Durable Objects и современных AI SDK.
* **Secretary Node (Раннер): Go**  
  Идеален для локальных демонов и системных раннеров. Компилируется в один статический бинарник без зависимостей, нативно держит PTY-терминалы, запускается за 10 мс на любой платформе.
* **Почему НЕ Rust для ядра Секретаря:**  
  Rust незаменим для упаковки CPU-bound алгоритмов в WebAssembly (как компилятор TS Rust в видео Тео). Но для сетевого демона и очередей задач связка **TypeScript (Edge) + Go (Node)** дает максимальную продуктивность разработки и нулевой оверхед по сборке.

## 8. Практические шаги для реализации в `secretary-v2`

1. **Фаза 1 (Текущая основа на Go):**
   * Сохранить ядро `secretaryd` и раннер `secretary-node` на Go.
   * Добавить абстракцию провайдеров инференса (поддержка CLI-сессий Claude Code и ACP).
2. **Фаза 2 (Cloud Control Plane):**
   * Реализовать адаптер `secretary-cloud` на базе **Cloudflare Durable Objects** (`@cloudflare/agents` или чистый Durable SQLite).
   * Обеспечить подключение локальных нод через исходящий WSS-туннель.
3. **Фаза 3 (On-Demand MicroVM Runner):**
   * Добавить диспетчер облачных контейнеров (Fly Machines API или E2B API).
   * Если локальные ноды пользователя недоступны более 15 секунд при получении задачи на код — поднимать временный контейнер с бинарником `secretary-node`, выполнять задачу и гасить контейнер.
