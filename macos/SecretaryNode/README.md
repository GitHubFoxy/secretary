# Secretary Node menu bar companion

On macOS 13+, the normal `secretary setup` flow builds and installs a signed, Spotlight-discoverable **Secretary Node.app** in `~/Applications`. Upgrades run the same installer and replace the bundle without touching the OS Launch at Login preference. You can also run `bash macos/SecretaryNode/install.sh` from a configured checkout. Xcode command-line tools (Swift) and `codesign` are required. The signing step uses local ad-hoc signing for self-hosted installations; distributing a notarized binary requires a separate Developer ID release process.

Use Spotlight to open **Secretary Node**. This is a menu bar-only app with native system light/dark appearance. It owns a single managed Node, using the existing `~/.local/bin/secretary-node` executable and `~/.local/share/secretary/node/config.json`; optional `SECRETARY_NODE_EXECUTABLE` and `SECRETARY_NODE_CONFIG` overrides are preserved. Do not install the legacy `secretary node install-service` LaunchAgent alongside the app. If that service exists, run `secretary node uninstall-service` before installing the app. The installer refuses to proceed while that service is installed or loaded.

The menu shows Node, Server, a separator, discovered harnesses, **Launch at Login**, **Open Logs**, and **Quit Secretary Node**. Launch at Login uses the macOS ServiceManagement setting and persists across relaunch and app upgrades. Quit gracefully stops the verified managed Node before exiting; reopening from Spotlight starts or recovers the managed Node. The log at `~/Library/Logs/SecretaryNode/node.log` captures managed Node stdout/stderr across restarts. Open Logs opens that file in the default registered app, or displays an actionable error when missing or inaccessible. The app does not adopt arbitrary external Node processes, manage the Server, or silently stop unrelated services.

CI smoke: `swift test --package-path macos/SecretaryNode` and `bash macos/SecretaryNode/install.sh` (with a configured Node binary). The macOS workflow exercises fresh install, replacement upgrade, bundle signature and conflict rejection. Manual checks: Spotlight indexing and relaunch; actual login/logout login item enable/disable and upgrade persistence; native dark/light appearance and menu layout; live Node start/stop and reopened log content; behavior with a real configured Server and harness.
