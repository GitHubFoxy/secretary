# Проверка стандартов: длительности обработки voice

Дата: 2026-10-11. База: `276aca40a30970b386079c3b0a5e8e8764213bda`. Проверены изменения `voice.go`, `voice_test.go`, новый `voice_timing_test.go` и связанные документы. Посторонние пользовательские изменения исключены.

Подтверждённых ошибок, нарушений документированных стандартов и значимых замечаний по эвристикам Fowler не найдено.

Метрики используют `time.Now`/`time.Since`, сохраняют монотонную основу измерения и не зависят от часов `CreatedAt`. `processing_ms` вычисляется до сохранения состояния, Telegram-уведомлений и передачи ввода агенту. Durations отдельно измеряют download, вызов ASR и вызов форматтера; отключённая/недоступная стадия форматирования получает 0. Статусы не смешивают недоступность форматтера с ранним сбоем до его вызова.

Объект timing сохраняется вместе с transcript; путь повторной доставки не пересчитывает метрики и не добавляет вызовов моделей. Optional pointer с `omitempty` сохраняет совместимость старых записей без timing. Изменения не затрагивают включение форматтера или runtime-конфигурацию.

В журнал передаются только числовые identity, длительности и фиксированные строковые статусы. Raw/formatted, audio, file ID, секреты и исходные тексты ошибок в новые log calls не попадают. При download/ASR failure измерение завершается до уведомления; formatter fallback сохраняет время неудавшегося вызова.

Тесты временно перенаправляют стандартный logger и восстанавливают его через defer; `t.Parallel` в пакете не используется. Независимо выполнено:

`go test -race ./internal/telegram -run 'TestVoiceTimings|TestVoiceFailureElapsed|TestVoiceTranscriptLegacy|TestVoiceRetry' -count=1 -timeout 30s`

Результат: успешно. Проверены persistence/replay, failure privacy, совместимость старого JSON и отсутствие гонок в этом наборе. Полные тесты из implementation report и состояние production я самостоятельно не проверял; SSH и deployment не выполнялись.
