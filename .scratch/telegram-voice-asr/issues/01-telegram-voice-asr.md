# 01: Telegram voice — локальный Parakeet и GPT-6 Luna

Type: task
Status: claimed
Blocked by: None

## Что сделать

Реализовать [спецификацию первой версии](../spec.md): Telegram voice → локальный `nemo-speech` с `parakeet-tdt-0.6b-v3.q8_0.gguf` → облачный OpenAI-форматтер GPT-6 Luna без thinking → существующий текстовый ввод Secretary/Worker.

Первая версия поддерживает один ASR engine и одну локальную ASR-модель, один облачный formatter provider. В `config.yaml` под `# ASR` можно менять formatter model и путь `prompt: formatter.md`, отключать форматтер, задавать путь к весам, API-ключ через имя env-переменной и согласованные лимиты. Переключение на облачный ASR, другие engines и локальные форматтеры не входят в эту задачу.

## Согласованное поведение

- Использовать валидный formatted текст; при отключении/ошибке форматтера или обнаруженной порче защищённых элементов — raw.
- Сохранять raw и успешный formatted рядом с исходной message identity; агент получает один итоговый ввод.
- `asr.show_asr_in_chat: false` по умолчанию: не показывать отдельную расшифровку; `true` показывает итоговый переданный агенту текст в исходном chat/topic. Обработка продолжается без отдельного подтверждения каждой диктовки.
- Сохранять порядок voice и text внутри chat/topic; разные topics независимы, локальный ASR запускается по одному.
- Лимиты: 120 секунд аудио, 10 000 000 bytes, ASR timeout 90 секунд, formatter timeout 20 секунд.
- Не передавать агенту пустой ввод при сбое ASR. При сбое форматтера использовать raw с кратким уведомлением.

## Критерии приёмки

- [ ] Локальный ASR использует выбранные engine и веса; RU/EN voice проходят обработку.
- [ ] OpenAI formatter использует выбранную модель без thinking; точный model ID и API-параметры проверены, несовместимость не маскируется подменой.
- [ ] `config.yaml` поддерживает согласованные поля; formatter model изменяем, промпт читается из Markdown-файла относительно директории config; неподдерживаемые mode/engine/provider явно отклоняются.
- [ ] Согласованный промпт и проверки сохраняют имена, числа, отрицания, идентификаторы и самоисправления; при выявленной порче используется raw.
- [ ] Secretary и Worker получают итоговую расшифровку через существующий путь с исходными chat/topic/message identity и правилами Steering message.
- [ ] Оба значения `show_asr_in_chat` проверены: `false` скрывает отдельную расшифровку, `true` показывает переданный агенту текст; raw/formatted сохраняются без создания двух запросов.
- [ ] Соблюдены порядок voice/text, независимость topics и один локальный ASR одновременно.
- [ ] Replay update и restart не создают повторного ввода или повторного исполнения.
- [ ] Владелец и допустимость chat проверяются до скачивания; API-ключи не попадают в YAML/ответы/логи.
- [ ] Лимиты и ошибки download/ASR/formatter дают согласованное поведение; временные файлы удаляются после успеха и ошибки, очередь освобождается после отказа.
- [ ] Выполнены необходимые интеграционные проверки и живая проверка Telegram; обычный текстовый ввод и Hermes сохраняют работу.
