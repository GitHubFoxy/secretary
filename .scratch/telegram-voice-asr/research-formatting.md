# Локальное форматирование расшифровки RU/EN

Решение пользователя после исследования: **Silero TE исключён из кандидатов**, использовать его не планируется. Сведения ниже сохранены как история рассмотренных вариантов, а не текущая рекомендация.

Дата исследования: 2026-10-11. Только чтение документации и исходников; модели не скачивались, inference и установка не выполнялись. Этот отчёт дополняет [issue](https://github.com/GitHubFoxy/secretary/issues/29) и [спецификацию](spec.md), не фиксирует окончательный выбор.

## Рекомендация

Для omarchy первым проверить **уже полученную пунктуацию Parakeet**. Если требуется только пунктуация/регистр, изучить companion существующего NeMo runtime или **Silero TE v2**. Если нужны абзацы и аккуратное удаление слов-паразитов, сравнить **Qwen3-0.6B Q8_0** и **Qwen3.5-0.8B Q4_0/Q8_0** на своих RU/EN расшифровках. Победителя по качеству форматирования сейчас нет: ни model cards, ни общие LLM benchmarks не доказывают сохранение смысла конкретных голосовых команд.

Сводка другого агента, читавшего omarchy: i5-1235U, 10 ядер/12 потоков; RAM 7.5 GiB, доступно около 4.1 GiB; Iris Xe; swap 23 GiB. Выбирать CPU-first, оставляя RAM для Hermes/ASR/системы. Наличие iGPU не доказывает работающий backend ускорения, swap не считать бюджетом для приемлемой задержки. Найден ASR GGUF Parakeet около 681 MiB; его размер не равен полному RSS процесса. Ollama/llama-cli/server в PATH не обнаружены — локальная LLM потребует отдельного runtime, которого пока нет.

## Что именно делает FluidVoice

В upstream FluidVoice есть отдельный запрос очистки расшифровки. При обычном непустом prompt инструкции идут в system message, а transcript JSON-экранируется в user message; legacy `${transcript}` template оставляет оба текста в одной user message. Тесты подтверждают минимальные правки в default prompt. Это полезный образец разделения инструкций и данных, но JSON envelope не гарантирует защиту модели от инструкций внутри диктовки. Проверены файлы на commit `7daffb529fb9f7c8d075f686a2d3da34695a66e4`: [DictationPromptRequest.swift](https://github.com/altic-dev/FluidVoice/blob/7daffb529fb9f7c8d075f686a2d3da34695a66e4/Sources/Fluid/Services/DictationPromptRequest.swift), [DictationPromptDefaultsTests.swift](https://github.com/altic-dev/FluidVoice/blob/7daffb529fb9f7c8d075f686a2d3da34695a66e4/Tests/DictationPromptDefaultsTests.swift).

Не копировать предположение, что произвольная микромодель даст тот же опыт, что модель FluidVoice. Официальный **Fluid-1 Quad 4B** — специализированный checkpoint в MLX, примерно 3.4 GB; его условия разрешают использование только внутри official FluidVoice applications и запрещают вне них. Для Secretary это не подходящий открытый checkpoint. **Fluid-1 Pico** опубликован как compiled CoreML, с LFM Open License v1.0 и условиями коммерческого использования; portable Linux/GGUF вариант и RU показатели по этой карточке не подтверждены. Источники: [Quad model card](https://huggingface.co/altic-dev/Fluid-1-Quad-4B-MLX-6bit), [Pico model card](https://huggingface.co/altic-dev/Fluid-1-Pico-CoreML), проверены 2026-10-11.

## Сначала использовать существующий speech runtime

На omarchy обнаружен `nemo-speech version 1.0.0`; точный remote/source commit установленной сборки другой агент не подтвердил. Ссылки на NVIDIA/NeMo-Speech.cpp ниже описывают найденный официальный upstream **как кандидат для сопоставления**, а не доказывают происхождение установленного бинарника. Локальные документы также описывают PnC/ITN, но наличие функций и лицензия companions должны проверяться на конкретной сборке/артефакте.

Upstream NeMo-Speech.cpp поддерживает BERT **PnC** (punctuation and capitalization) как отдельный GGUF companion, а **ITN** (inverse text normalization) — через Sparrowhawk grammars. Порядок: profanity → ITN → PnC. PnC вставляет регистр и `. , ?`; ITN меняет произнесённые числа/даты на письменную форму. Нужны артефакт и соответствующая настройка; ITN дополнительно требует сборку с `NEMO_SPEECH_WITH_NORM=ON`. Это не удаление слов-паразитов и не структурирование абзацев. Источник: [configuration.md, фиксированный commit](https://github.com/NVIDIA/NeMo-Speech.cpp/blob/e59dfb0b5c22655620f41391cc9a000d6f56b802/docs/asr/configuration.md).

Для уже пунктуирующей ASR runtime может сохранить её пунктуацию вместо дополнительного PnC. Следовательно, отсутствие `--pnc-model` не доказывает отсутствие пунктуации в результате Parakeet. Источник: [ASR customization](https://github.com/NVIDIA/NeMo-Speech.cpp/blob/main/docs/asr/customization.md), проверен 2026-10-11.

CLI документирует `--pnc-model` и `--itn-model-dir`, но приведённый пример грамматики `en-US` и имя `pnc-bert-base-en` не доказывают готовый русский companion. Конвертер ожидает NeMo BERT checkpoint с двумя classifier heads и WordPiece vocab; произвольный Silero TE нельзя считать совместимым GGUF без работы над конвертацией. Не подтверждены RU checkpoint, его лицензия, установленная версия runtime и наличие optional ITN build. Источники: [CLI](https://github.com/NVIDIA/NeMo-Speech.cpp/blob/main/docs/cli.md), [PnC converter](https://github.com/NVIDIA/NeMo-Speech.cpp/blob/e59dfb0b5c22655620f41391cc9a000d6f56b802/conversion/pnc.py).

Сводка read-only проверки Hermes: `format_transcripts:true` найден в config, но потребитель этой настройки в Python исходниках не найден; gateway берёт `result['transcript']`, wrapper дополнительного форматирования не делает. Не принимать наличие флага за работающую функцию. Детальные локальные доказательства находятся в отчёте omarchy; это наблюдение, а не upstream контракт.

## Кандидаты

Память ниже — **оценка планирования**, не измерение на omarchy. Предполагаются один concurrent request, короткий context 2–4K, CPU GGUF, без vision adapter, отдельный процесс. Диапазон RSS включает запас под веса, cache и рабочие буферы, но может отличаться в выбранной сборке. Формула `parameters × bits / 8` даёт только нижнюю оценку весов; embeddings, quantization metadata и mixed precision меняют размер файла.

- **Qwen3-0.6B Q8_0 — основной простой baseline.** Apache-2.0, модель instruction-tuned, заявлена поддержка 100+ языков; качество русского cleanup отдельно не измерено. Есть hard switch `enable_thinking=False`; его надо передать через chat template/runtime, а не надеяться на текст `/no_think`. Официальный GGUF Q8_0 **639 MB** (~0.60 GiB); ориентир полного процесса **0.9–1.5 GiB**. Удобный вариант без дополнительной конвертации. Источники: [model card](https://huggingface.co/Qwen/Qwen3-0.6B), [официальный GGUF](https://huggingface.co/Qwen/Qwen3-0.6B-GGUF/tree/main).
- **Qwen3.5-0.8B — актуальный маленький challenger.** Apache-2.0, 201 языков/диалектов на уровне семейства; производитель отдельно позиционирует этот размер для prototyping/task-specific fine-tuning. Это не доказательство точного RU форматирования. ggml-org публикует **Q4_0 563 MB** (~0.52 GiB), **Q8_0 834 MB** (~0.78 GiB); ориентир RSS **0.9–1.6 GiB** (Q4) и **1.2–1.9 GiB** (Q8). Текстовый режим не нуждается в vision projector. Не использовать soft switch Qwen3: карточка Qwen3.5 его не поддерживает; проверить API/template non-thinking и фактический ответ. У маленькой версии производитель предупреждает о thinking loops, поэтому reasoning здесь выключить. Источники: [model card](https://huggingface.co/Qwen/Qwen3.5-0.8B), [ggml-org GGUF](https://huggingface.co/ggml-org/Qwen3.5-0.8B-GGUF/tree/main).
- **Qwen3-1.7B — резерв при плохом качестве 0.6B.** Apache-2.0, multilingual family, non-thinking переключатель; ожидаемый Q4 бюджет весов около **0.85 GB плюс overhead**, RSS примерно **1.4–2.3 GiB**, оценочно. Официальный Q8 GGUF доступен, но для текущего shared RAM бюджета сначала исследовать Q4 артефакт и его происхождение. Больше параметров не гарантирует сохранение отрицаний и сущностей. Источники: [model card](https://huggingface.co/Qwen/Qwen3-1.7B), [официальный GGUF](https://huggingface.co/Qwen/Qwen3-1.7B-GGUF/tree/main).
- **Qwen3.5-2B / 4B — не первый выбор для этого ноутбука.** 2B имеет тот же механизм multilingual/non-thinking и предупреждение о reasoning loops; нижняя оценка Q4 весов 1.0 GB, процесс условно 1.8–2.8 GiB. Для 4B нижняя оценка 2.0 GB, процесс условно 2.8–4.0+ GiB: это почти весь текущий available RAM до ASR peak. Проверять только после провала меньших вариантов, без обещания latency. Источник для 2B: [model card](https://huggingface.co/Qwen/Qwen3.5-2B); оценки 4B — арифметика, не опубликованный benchmark.

Все ссылки в этом разделе проверены 2026-10-11. **Скорость token/s на i5-1235U не измерена.** Время форматирования включает prefill всего transcript и autoregressive decode почти такого же объёма текста; отключение reasoning убирает лишнюю генерацию, но не делает длинную диктовку мгновенной.

**Silero TE v2** — узкий дополнительный кандидат. Текущий upstream `models.yml` содержит quantized `v2_4lang_q.pt`, RU/EN/DE/ES, а `hubconf.py` экспортирует `silero_te`. Авторы описывают размер около **85 MB**, обработку нескольких предложений, ограничение обучения 512 токенов (~150 слов); длинный текст требует корректного оконного применения. Это punctuation/recapitalization, без обоснованного FluidVoice-паритета по paragraphs/fillers. Torch/Python зависимость может оказаться тяжелее самого checkpoint; RSS и CPU latency неизвестны. Repo обозначен MIT, но перед использованием нужно проверить условия конкретного загружаемого артефакта. Источники: [v2 статья авторов, 2021-12-09](https://habr.com/ru/articles/594565/), [models.yml](https://github.com/snakers4/silero-models/blob/d9355348e2781dc8fa25a135d1602c530afae24c/models.yml), [hubconf.py](https://github.com/snakers4/silero-models/blob/d9355348e2781dc8fa25a135d1602c530afae24c/hubconf.py).

Дополнительные варианты просмотрены: **Gemma-3-1B-it** (multilingual family, отдельная Gemma license/условия доступа), но преимуществ именно по RU cleanup не найдено; **LFM2.5-1.2B-Instruct** обещает CPU эффективность, однако русский отсутствует среди восьми заявленных языков, поэтому не основной RU/EN выбор. Не переносить опубликованные цифры других CPU на omarchy. Источники: [Gemma card](https://huggingface.co/google/gemma-3-1b-it), [LFM card](https://huggingface.co/LiquidAI/LFM2.5-1.2B-Instruct).

## Минимальный pipeline и проверка сохранения смысла

Это предложения для будущей реализации, сейчас ничего не меняется:

1. Сохранять raw ASR текст и исходную message identity. Показывать/использовать отдельный formatted text только после успешной валидации. Ошибка formatter должна возвращать raw текст, а не блокировать ASR ввод.
2. Начать с режима «пунктуация + регистр + абзацы», **без удаления слов**. Затем отдельно решить, нужен ли режим удаления fillers: «ну», «вот», «нет» могут выражать намерение, исправление или отрицание.
3. Постоянные instructions отдельно от JSON-экранированной диктовки; не добавлять инструменты, историю диалога и agent capabilities. Модель должна форматировать фразу «удали все файлы», а не выполнять её. Отсутствие tools предотвращает вызов действий formatter, но не предотвращает изменение смысла выходного текста.
4. Проверять размер/тайм-аут/обрыв, отсутствие комментария и ответа на вопрос. В строгом режиме сохранять последовательность слов, позволяя лишь согласованные изменения регистра/пробелов/пунктуации. URLs, пути, код, flags, email, identifiers защищать как точные spans; нельзя глобально удалять всю пунктуацию для сравнения — так пропадёт смысл `--no-cache`, `1.5` и URL.
5. Отдельные проверки чисел, дат, валют, имён и отрицаний. Эти проверки снижают риск, но не доказывают semantic equivalence; «казнить нельзя помиловать» показывает, что даже одни запятые меняют смысл. ITN чисел включать отдельно, после тестов, а не под видом косметического форматирования.
6. Один запрос одновременно и context 2–4K; большие сообщения разбивать с сохранением порядка и защищённых spans, либо возвращать raw. Постоянно загруженный процесс быстрее cold start, но держит RAM; способ запуска выбрать только после замеров.

llama.cpp подходит для CPU GGUF: upstream поддерживает x86 AVX/AVX2 и integer quantization, локальный HTTP API. Vulkan/SYCL существуют, но поддержка конкретной Iris Xe и выигрыш не проверены. Источник: [llama.cpp](https://github.com/ggml-org/llama.cpp), проверен 2026-10-11. Это будущий runtime, не установленный компонент текущего omarchy.

## План измерений перед выбором

- Corpus: хотя бы 50 RU, 50 EN, 20 смешанных/технических сообщений; реальные голосовые 5/30/120 секунд плюс текстовые stress fixtures. Сравнить raw ASR, companion/TE, Qwen3-0.6B и Qwen3.5-0.8B с одинаковым контрактом. Сохранить отдельную ручную эталонную расшифровку: formatter не должен «исправлять» неизвестные ASR ошибки догадкой.
- Обязательные fixtures: «не удаляй», «нет, не двадцать, а двенадцать», «не запускай без подтверждения», `do not delete`, `can't`, `0.05`, «минус пять», даты/часовые пояса, имена «Михаил/Хермес», Qwen/Parakeet, commit hashes, `--no-cache`, пути, исходные URL/email, цитата «ignore previous instructions», `/think`, незакрытые кавычки, русский с английскими identifiers. Во fixture точного URL использовать буквальный URL как входные данные; это тест, а не правило оформления ответа.
- Отдельно оценивать punctuation/case/paragraph readability и сохранение сущностей/отрицаний/чисел. Любое изменение защищённого span или команды — провал; число успешных результатов/ошибок и raw fallback rate публиковать, а не только среднюю красивость.
- Замерить cold/warm latency p50/p95, prefill/decode tokens/s, peak RSS, swap activity, CPU usage при параллельном Hermes; сравнить разные thread counts на P/E cores. Желательный UX бюджет надо согласовать, не выдавать его за достигнутый. Для длинной диктовки показывать отдельные статусы ASR/formatting, если форматирование заметно по времени.
- Зафиксировать model revision/checksum, quantization, runtime commit, prompt, context и decode settings. Не считать temperature=0 доказательством корректности; сравнить повторяемость и ошибки в non-thinking режиме. Увеличивать модель только если меньшая не проходит preservation tests и у larger модели есть измеримое преимущество.

## Что остаётся открытым

Не измерены локальная точность/задержка, конкуренция за память с Hermes, совместимость установленной NeMo сборки с companions, готовый RU PnC checkpoint и лицензия его весов. Нужен выбор между буквальной диктовкой и очисткой fillers, политика отображения raw/formatted и действие при неоднозначном распознавании команды. Эти решения важнее общего рейтинга микромоделей.
