# Методика и спецификация тестирования локальных ASR на omarchy (Intel i5-1235U)

**Дата:** 11 октября 2026  
**Статус:** Исследовательская спецификация и проверенная методика (документация для родительского агента; без SSH, без запуска моделей, без изменения зависимостей).  
**Целевой узел:** `omarchy` (Arch Linux, Intel Core i5-1235U [2 P-cores + 8 E-cores, 12 аппаратных потоков], 7.5 GiB RAM, iGPU Iris Xe).

---

## 1. Фактический план родительского агента и статус моделей

Тестирование выполняется родительским агентом последовательно и строго в рамках имеющихся в системе артефактов без установки сторонних пакетов (`faster-whisper` и `CTranslate2` отсутствуют в системе и **не устанавливаются**).

| Модель / Конфигурация | Среда исполнения | Файлы / Веса | Проверяемый набор | Текущий статус |
|---|---|---|---|---|
| **Native Parakeet Q8** | C++ бинарник `nemo-speech` (источник не подтвержден, ggml) | `parakeet-tdt-0.6b-v3.q8_0.gguf` (681 MiB) | 5 клипов (RU / EN) | Включен в план |
| **Parakeet ONNX int8** | `onnx-asr` (ONNX Runtime CPU) | Полный набор INT8 весов и конфигов `onnx-asr` | 3 клипа | Включен в план |
| **GigaAM-v3 RNNT int8** | `onnx-asr` (ONNX Runtime CPU) | `v3_rnnt_encoder.int8.onnx`, `v3_rnnt_decoder.int8.onnx`, `v3_rnnt_joint.int8.onnx`, `v3_vocab.txt`, `config.json` | 2 клипа (RU) | Включен в план |
| **Whisper base ONNX int8** | ONNX Runtime CPU | Квантованная база ONNX INT8 (без CTranslate2) | 5 клипов (RU / EN) | Включен в план |
| **GigaAM-v3 E2E RNNT** | `onnx-asr` (ONNX Runtime CPU) | Комплект E2E пока не скачан и не проверен | — | **Не тестировался** (отложен) |
| **Whisper small** | — | — | — | **Не тестировался** (отложен) |

### Критические уточнения по моделям:
1. **Происхождение `NeMo-Speech.cpp`:** Источник установленного в системе бинарника `nemo-speech` не подтвержден официально; его нельзя приписывать NVIDIA без прямых доказательств (сторонний/неофициальный C++ порт на базе ggml).
2. **Квантование GigaAM в `onnx-asr`:** В режиме INT8 используются все квантованные компоненты (`encoder.int8.onnx`, `decoder.int8.onnx`, `joint.int8.onnx`), а не гибридная связка с FP32.
3. **E2E пунктуация vs LLM-форматирование:** Наличие E2E пунктуации в модели (точки, запятые, вопросительные знаки) делает текст более читаемым, но **не заменяет произвольное LLM-форматирование** (структурирование заметок, выделение пунктов, исправление контекстных оговорок, оформление списков).

## 2. Реально проверенные системные ограничения и безопасность

Для ограничения нагрузки на рабочую среду и критические сервисы (`hermes-gateway.service`) запуск тестов строго регламентирован следующими параметрами:

### Проверенные параметры изоляции (`systemd-run`)
- **Последовательный запуск:** Модели запускаются строго по одной.
- **Ограничения ресурсов:**
  ```bash
  systemd-run --user --wait --pipe --collect --unit=<уникальное-имя> \
    -p MemoryMax=2G \
    -p MemorySwapMax=0 \
    -p CPUQuota=150% \
    -p Nice=15 \
    -p RuntimeMaxSec=90s \
    taskset -c 0,2 <команда>
  ```
- **Конфигурация потоков и привязка ядер:**
  - На гибридной архитектуре Intel Alder Lake (2 P-ядра с HT + 8 E-ядер) указание `threads=4` **не гарантирует** выполнение только на P-ядрах: планировщик Linux без жесткой аффинити может распределять задачи по энергоэффективным E-ядрам.
  - Утверждение о замедлении на 30–50% без привязки являлось неподтвержденной гипотезой и экспериментально на узле не измерялось.
  - Проверенный профиль: `taskset -c 0,2` и `threads=2`.
- **Потребление памяти (Peak RSS):**
  - Априори гарантировать Peak RSS < 1.5 GiB для всех конфигураций и длительностей аудио невозможно.
  - Жесткий потолок задается через `MemoryMax=2G`.
  - `MemorySwapMax=0` запрещает подкачку тестовому cgroup; это не отключает подкачку остальных процессов хоста.

### Стоп-триггеры (Pre-flight checks)
Перед запуском каждого отдельного теста выполняется проверка состояния хоста:
1. **Память:** Немедленная отмена запуска, если доступный объем памяти `MemAvailable < 2 500 000 kB`.
2. **Температура:** Немедленная отмена запуска, если максимальная температура доступных thermal zones непосредственно перед стартом `>= 85°C`.
> **Важно:** Постоянный непрерывный температурный контроль во время самого инференса не гарантируется и не обещается; проверка проводится исключительно перед запуском процесса.

## 3. Методология измерений времени и метрик

### Ограничения окружения
- Утилита `/usr/bin/time` в системе **отсутствует**. Замеры производятся средствами внутреннего тайминга (`time.monotonic()` в Python) или через метрики завершения systemd.

### Разделение этапов
Измерение сквозного времени разбивается на изолированные фазы:
1. `T_ffmpeg`: Конвертация исходного аудио Telegram (`.ogg` Opus) в PCM 16 kHz моно (`ffmpeg -nostdin -threads 1 ...`). Замеряется отдельно от инференса.
2. `T_load`: Инициализация среды выполнения и загрузка весов в память:
   - Реально измеренные значения загрузки ONNX на данном хосте:
     - **Parakeet ONNX:** 2.76–3.29 с.
     - **GigaAM ONNX:** 1.037–1.195 с.
   - Прежняя гипотетическая оценка 0.8–1.5 с для всех моделей опровергнута реальными измерениями.
3. `T_infer`: Чистое время обработки подготовленного 16 kHz аудио буфера моделью.
4. `runner_seconds`: запуск ONNX-раннера, включая импорты, загрузку и распознавание; ffmpeg исключён. Native `asr_process_seconds` включает весь процесс ASR, но исключает внешний Python-раннер и ffmpeg. Ни одна метрика не измеряет полный путь Telegram.

### Особенности дискового кэша
Запуск нового процесса не означает «холодный» дисковый кэш. Системный page cache операционной системы между запусками **не сбрасывается** (`drop_caches` не выполняется), поэтому веса могут читаться из кэша страниц; фактический источник каждого чтения не измерялся.

## 4. Оценка качества распознавания

1. **Метрика WER:**
   - Вычисление Word Error Rate (WER) **не производится** без независимо верифицированного ручного эталона транскрипции (ground truth).
   - Автоматический расчет WER на базе выходов других моделей в качестве псевдо-эталона недопустим.
2. **Репрезентативность выборки:**
   - Тестовый набор из 5 личных аудиозаписей достаточен для предварительной качественной проверки работоспособности, оценки базовой читаемости и выявления грубых сбоев/галлюцинаций.
   - Данный объем **категорически недостаточен** для формирования статистически значимого лидерборда или ранжирования качества моделей.

## 5. Ограничения методики и следующий эксперимент

### Текущие ограничения
- Отсутствие верифицированного эталонного текста для автоматического подсчета WER.
- Малый объем тестового аудиосета (5 клипов).
- Отсутствие непрерывного телеметрического контроля температур во время инференса.

### Следующий разумный эксперимент
1. **Завершение базового прогона родительским агентом:** Выполнение фактического плана (Parakeet Native Q8 на 5 клипах, Parakeet ONNX int8 на 3 клипах, GigaAM-v3 RNNT int8 на 2 RU клипах, Whisper base ONNX int8 на 5 клипах) с жестким соблюдением профиля `systemd-run` и фиксацией `T_load`, `T_infer` и Peak RSS.
2. **Качественная верификация выходов:** Экспертная оценка читаемости, корректности распознавания специализированных терминов и стабильности на паузах.
3. **Подготовка эталона:** При необходимости количественного сравнения точности — ручная разметка проверочных клипов для корректного расчета WER.
4. **Оценка кандидатов следующей очереди:** Тестирование GigaAM-v3 E2E RNNT и Whisper small только после подтверждения запаса по памяти и стабильности базового набора.
