# Ссылки в ответах только по явному запросу

Status: needs-triage

## Цель

Убрать URL из пользовательских ответов Secretary и Worker по умолчанию: ссылки на источники, цитирования, доказательства и другие материалы занимают слишком много места в Telegram из-за отображения и preview.

## Правила

- Если пользователь явно не попросил URL или ссылку, не добавлять URL в ответ ни в сыром виде, ни в Markdown. Это относится также к citations, proof и source links.
- Если пользователь явно попросил URL или ссылку, всегда оформлять её как Markdown-ссылку с коротким понятным названием: `[название](https://example.com/page)`. Не показывать сырой URL.
- Проверять факты и использовать источники по-прежнему. Отсутствие ссылки в ответе не отменяет проверку, указание неопределённости и честный отчёт о результате.
- Применить правило к Secretary и Worker, включая краткие результаты и сообщения с доказательствами. Хранить общие инструкции в соответствующих profiles, без повторяемого boilerplate в каждом Task prompt.
- Проверить Telegram Markdown→HTML путь, чтобы явно запрошенные ссылки корректно отображались как кликабельные названия. Для таких сообщений отключить link preview, чтобы карточка снова не занимала место в topic или General.

## Границы

Изменение касается новых пользовательских ответов. Не переписывать историю, исходные сообщения пользователя, код, конфигурацию, tool payloads и необходимые URL внутри создаваемых по запросу технических материалов. Не удалять ссылки механической заменой из произвольного содержимого.

При внедрении учитывать external profile paths: изменение embedded defaults само по себе не обновляет фактически настроенные profiles.
