# Читаемое отображение таблиц и структурированных данных в Telegram

Status: needs-triage

## Проблема

Пользователь сообщил о сломанном и нечитаемом форматировании таблиц в Telegram (сообщение с переводом слова «пачкать» в разных контекстах). 

Когда Worker возвращает результат в виде стандартной Markdown-таблицы (GFM table с разделителями `|` и строкой `|---|---|---|`):
1. Telegram Bot API не имеет нативной поддержки тегов `<table>`/`<tr>`/`<td>`.
2. Текущий форматтер `formatTelegramChunk` в `internal/telegram/format.go` не обрабатывает таблицы и передаёт строки таблицы как обычный текст.
3. В узких мобильных экранах и чат-пузырях Telegram строки с несколькими колонками неизбежно переносятся на новые строки. Разделители `|` оказываются в случайных местах текста, заголовки отрываются от ячеек, разделители `|---|---|---|` загромождают сообщение, и таблица превращается в нечитаемую «кашу».
4. Одиночные звёздочки курсива внутри ячеек (например, `*Don’t get your clothes dirty.*`) не преобразуются в Telegram `<i>`, оставаясь сырыми символами `*`.

## Известный контекст

1. **Telegram delivery pipeline:**
   - Worker завершает задачу, результат попадает в durable store как `worker.completed` / `result.accepted`.
   - Telegram bridge (`cmd/secretaryd/telegram.go`, `internal/telegram/adapter.go`) отправляет результат в Worker Topic, а также зеркалирует его в General (`topicName("", mapping.Title) + ":\n" + body`).
   - Сообщение нарезается на чанки функцией `prepareTelegramChunk` (`internal/telegram/adapter.go:1295`), а затем форматируется в `formatTelegramChunk` (`internal/telegram/format.go:17`).
   - `formatTelegramChunk` преобразует только блоки кода ` ``` ` в `<pre>`, заголовки `# ` в `<b>`, ссылки `[label](url)` в `<a>`, инлайн-код `` ` `` в `<code>` и жирный текст `**`/`__` в `<b>`. Всё остальное экранируется и выводится как сплошной текст.
2. **Web UI:**
   - В Web клиенте (`web/src/Markdown.svelte`, `web/src/app.css`) таблицы обрабатываются библиотекой `markdown-it` и имеют CSS-стили со скроллом (`display: block; overflow-x: auto; border-collapse: collapse;`). Там таблицы отображаются корректно.
3. **Промпты моделей:**
   - В `internal/config/defaults/worker.md` и `internal/config/defaults/secretary.md` нет явных ограничений или рекомендаций по оформлению табличных данных для мессенджеров. Модели (Codex, Claude) по умолчанию генерируют таблицы Markdown, когда их просят сравнить несколько вариантов или дать сводку.

## Что проверить и исправить

1. **Двухуровневое решение (Defense-in-depth):**
   - **Уровень промптов (Primary):** Добавить в профили `worker.md` и `secretary.md` правило, запрещающее использование Markdown-таблиц (`| ... |`) в ответах для мессенджера и предписывающее оформлять сравнения и многоколоночные данные в виде структурированных списков, блоков определений или ключ-значение (например, `• **Термин**: описание — пример`).
   - **Уровень форматтера Telegram (Fallback / Safeguard):** Научить `formatTelegramChunk` распознавать блоки Markdown-таблиц и трансформировать их в удобочитаемый структурированный вид (карточки/списки) без «сырых» пайпов `|` и пунктирных линий `|---|`, чтобы даже при случайной генерации таблицы моделью в Telegram никогда не попадал сломанный ASCII-макет.
2. **Безопасность и лимиты Telegram:**
   - Преобразование таблиц не должно ломать парсер Telegram HTML (не создавать невалидные теги).
   - Преобразование не должно выходить за лимит размера чанка (4096 UTF-16 units).
   - Plain fallback при parse error должен оставаться читаемым без пайпового мусора.
