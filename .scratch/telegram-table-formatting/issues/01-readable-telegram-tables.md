# 01: Читаемое форматирование таблиц и многоколоночных данных в Telegram

Type: task
Status: needs-triage
Blocked by: None

## Что сделать

Реализовать [спецификацию](../spec.md) для устранения сломанного отображения таблиц в Telegram:

1. **Профили моделей (`worker.md`, `secretary.md`):**
   - Добавить явную инструкцию о запрете Markdown-таблиц (`| ... |`) в ответах.
   - Предписать форматировать сравнения, переводы и многоколоночные данные в виде структурированных списков, карточек или блоков определений (например: `• **Слово / выражение**: описание \n  *Пример:* пример`).

2. **Форматтер Telegram (`internal/telegram/format.go`):**
   - Добавить распознавание блоков Markdown-таблиц (строки с разделителями `|`, строка заголовков и разделитель `|---|---|`).
   - Преобразовывать таблицу в читаемый мобильный формат списков/карточек без сырых пайпов `|` и пунктиров `|---|`.
   - Обеспечить корректный plain fallback без мусорных разделителей.
   - (Опционально/сопутствующе) поддержать базовый курсив `*` / `_` -> `<i>`, если он встречается внутри форматируемого текста.

3. **Сохранение гарантий доставки:**
   - Не превышать лимиты чанков Telegram (4096 UTF-16 единиц).
   - Сохранить идемпотентность outbox, дедупликацию и баланс HTML-тегов.
   - Не ломать существующее форматирование кода в `<pre>` и заголовков `<b>`.

## Критерии приёмки

- [ ] В ответах Secretary и Worker многоколоночные данные и сравнения не генерируются в виде Markdown-таблиц с пайпами `|`.
- [ ] Если во входном тексте для Telegram присутствует Markdown-таблица, форматтер `formatTelegramChunk` преобразует её в читаемый структурированный список или карточки вместо вывода сырых пайпов и пунктиров.
- [ ] В Telegram-сообщениях отсутствуют строки `|---|---|---|` и хаотичные переносы колонок с пайпами на мобильных устройствах.
- [ ] Преобразованный вывод корректно проходит валидацию Telegram HTML (не вызывает `400 Bad Request: can't parse entities`).
- [ ] Размер сформированного сообщения не превышает лимиты Bot API (4096 UTF-16 units на чанк); разбиение на чанки не разрывает HTML-теги.
- [ ] Форматирование таблиц в Web-клиенте (`Markdown.svelte`) сохраняется без регрессий.
- [ ] Unit-тесты в `internal/telegram/format_test.go` покрывают:
  - Простую таблицу из 2–3 колонок.
  - Таблицу с пустыми ячейками или разным числом колонок.
  - Таблицу с инлайн-форматированием (жирный шрифт, ссылки, код).
  - Пограничные случаи рядом с лимитом размера чанка.
  - Plain fallback без сырых пайпов.
