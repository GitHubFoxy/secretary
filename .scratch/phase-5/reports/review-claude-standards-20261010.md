До фактического native Result старый Claude process остаётся активным: закрытие добавлено лишь в `internal/node/execution_node.go:661`. Secretary server уже считает Worker idle и допускает queued/explicit Follow-up с новым process через прежний native transcript. Возможны одновременные executions/writers одной native session и преждевременная Task closure. Hard violation нового `docs/architecture/runtime-contracts.md`, Claude Code native Session: «Cancel ждёт native terminal; receipt не завершает Attempt». Session-only drain test проверяет локальный active flag, но не этот production call chain. Следует сохранять active Attempt до native terminal, либо делать synchronous cancel с terminal confirmation, согласовав существующий lifecycle.

- **P2 — заблокированный stdin делает Prompt и Close неотменяемыми.** `internal/node/claude_runtime.go:305,323,371–374`: Prompt держит writeMu во время blocking pipe write и проверяет context только перед записью. Close ждёт тот же mutex прежде закрытия stdin/kill. Если native process перестал читать и prompt заполнил pipe, deadline не завершает Prompt, Close не может остановить process. Это correctness finding: запрос и остановка Worker/Secretary зависают до внешнего убийства process. Воспроизведено через public Session: deferred fake CLI `exec sleep 30`, Prompt 1 MiB с deadline 50 ms, затем Close. Обе операции остаются заблокированными. Read-only Go overlay test `internal/node/claude_backpressure_test.go`; команда `mise exec -- go test -overlay /private/tmp/p5-cc-review-overlay.json ./internal/node -run '^TestReviewClaudePromptCancellationUnderBackpressure$' -count=1` — FAIL. Нужен путь закрытия pipe/process, не ожидающий заблокированного writer, и отменяемая запись.
