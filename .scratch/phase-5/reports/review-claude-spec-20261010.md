## Соответствие спецификации: CC increment

Сравнение: `acdba0c...c76434acd5ec20d78b5d0c30e2ffb78ad31e2027`.

1. **P1 — Cancel открывает доставку `/q` до terminal старой native CC Attempt.** `internal/node/claude_runtime.go:355` в сочетании с `internal/ctl/worker_lifecycle.go:827` и `internal/node/execution_node.go:191`. Issue 02: «Cancel/interrupt корректно завершает старую Attempt, не связывает её terminal с новым query»; Phase 5: «Она доставляется только после terminal Result текущей Attempt как новый Follow-up».

Новый `claudeSession.Cancel` лишь отправляет interrupt и сразу возвращает `nil`; Session остаётся active до native `result`. Но `WorkerService.CancelWorker` сразу сохраняет собственный terminal `Canceled by Secretary`. Production queue pump видит idle binding и запускает следующий Follow-up, хотя native runtime ещё выполняет старую Attempt. Durable ExecutionNode continuation не проверяет существование активной predecessor session и вызывает `--resume` той же native identity: появляются два process, пишущих один transcript, либо native resume отказывает, превращая корректный `/q` в blocked. Поздний настоящий terminal старой Attempt уже не определяет canonical Result. Пользователь получает успешную отмену и запуск следующей работы раньше фактического завершения предыдущей.

В отдельной копии репозитория воспроизведено через public Claude Session и WorkerService: fixture принимает interrupt, удерживает native terminal; `Session.Prompt` ещё возвращает active error, но после `CancelWorker → ProcessQueuedWorkerMessages` dispatch count уже равен 2. Тест `internal/ctl/worker_cancel_terminal_test.go`, `TestCCCancelDoesNotDeliverQueueBeforeNativeTerminal` — FAIL. Session-level существующий `TestClaudeCancelDrainsTerminalBeforeNextPrompt` проходит, поскольку самостоятельно ждёт Result и не проверяет server cancellation boundary. Необходимо сохранять cancel intent без освобождения Worker/queue до native terminal либо обеспечить подтверждённый terminal drain перед успешным lifecycle завершением.

Других доказанных неправильных реализаций и scope creep в CC increment не выявлено. Proxy quota403, отсутствие альтернативной авторизации и explicit unsupported steering/addressed grouping уже честно задокументированы; live acceptance остаётся открытой. Это не дополнительные findings. Предыдущие queue recovery/quickstart замечания в данный раунд не включены. Репозиторий не изменялся.
