# 01: Добавить X Channel adapter для ответов на упоминания `@SCRTRY`

Type: task
Status: ready-for-agent
Blocked by: None

## Проблема

Сейчас Secretary доступен через Telegram и Web. Владелец хочет обращаться к настроенному аккаунту `@SCRTRY` через X: упомянуть его в посте и получить ответ в этой же ветке. [Спецификация](../spec.md) и [исследование X API и границ реализации](../research.md).

Это один Channel adapter к общей Personal Conversation, а не отдельный Secretary или публичный сервис для произвольных X-пользователей. В X ответы публичны. До появления account linking разрешён только настроенный X user ID владельца; чужие упоминания должны игнорироваться.

## Что сделать

Добавить минимальный polling-first X Channel adapter по образцу существующего Telegram adapter, используя стандартную библиотеку Go и текущие серверные контракты там, где их достаточно.

- Вынести сетевое взаимодействие с X API в тестируемый транспорт: OAuth 2.0 user context, чтение mentions, отправка reply. Нужны только права для чтения постов/идентичности, публикации и обновления OAuth-токена; не запрашивать лишние scope.
- Добавить отдельную явную конфигурацию и запуск адаптера в `cmd/secretaryd`. По умолчанию интеграция выключена. X credentials не должны попадать в логи, ошибки, event payload, обычное состояние адаптера или ответы API. Refresh token хранить отдельно в защищённом файле credentials с правами `0600`; сохранять заменённый token, если OAuth response его возвращает, и восстанавливать его после restart.
- На первом запуске установить cursor на текущую верхнюю границу mentions, чтобы не отвечать на всю историческую ленту. Далее читать новые упоминания с pagination и безопасно восстанавливать обработку после restart. Гарантия ограничена окном последних 800 mentions X; при выходе cursor за окно явно сообщать владельцу о возможном пропуске.
- Принимать только новые текстовые посты, где автор совпадает с настроенным owner user ID, а адресованное упоминание совпадает с настроенным `@SCRTRY`. Игнорировать другие авторы, собственные посты аккаунта Secretary, неподдерживаемые посты и записи, уже сохранённые по внешнему ID. Использовать X entities для удаления адресного упоминания из текста, не удалять похожий текст автора.
- Сохранять вход через существующий `/v1/messages` contract с устойчивым внешним ID и корректной X client identity. Не переиспользовать Telegram credential или adapter identity.
- Связать обработанный входной X post с его Secretary turn и направлять единственный итоговый reply в публичную ветку исходного поста. Использовать существующий opt-in `Addressed reply v1` с точным `input_id`; если контракт выключен или origin link недоступен, безопасно отказаться от публикации. Не fallback-ить на legacy routing и не определять связь по тексту или последнему упоминанию. Не публиковать в X события Web/Telegram или другого X-ввода.
- Пометить X-ввод как публичный и формировать ограниченный public context: не передавать приватные записи Telegram/Web, локальные файлы, private Worker Workspace или credentials. В MVP не запускать Worker для X turn: текущий Worker имеет полный доступ к локальному Workspace, а одной фильтрации prompt недостаточно. Если запрос требует private material, не публиковать ответ и предложить владельцу продолжить в приватном канале. Не публиковать личные/закрытые сведения владельца или третьих лиц и unsolicited mentions других пользователей.
- На одно X interaction отправлять не более одного автоматического reply: только финальный текст Secretary. Не слать отдельный acknowledgement и не разбивать текст на несколько posts. Для ответа длиннее лимита X отправить один короткий reply с просьбой запросить сокращение; не усекать исходный результат молча.
- До включения получить явное согласие владельца на публичные автоответы, описать автоматизацию, предоставить простой opt-out (например, `@SCRTRY STOP`) и способ включить снова. Opt-out немедленно останавливает будущие автоответы, переживает restart и может быть изменён только owner account. Отвечать не более одного раза на каждый user interaction.
- Сохранять IDs исходного X post и созданного reply. Обнаруживать удаление/изменение posts, переход в protected/private, suspension и withholding; прекращать обработку такого контента и очищать/обновлять все Secretary-owned durable копии, включая Conversation entry и доступные transcripts/checkpoints. Прямой запрос X или владельца на удаление запускает немедленную задачу очистки; все затронутые копии должны быть удалены не позднее 24 часов с момента получения запроса. Предусмотреть проверяемый reconciliation путь без webhook.
- Сохранять cursor, обработанные ID и исходящие отправки так, чтобы replay входа не создавал повторного входа/ответа. Если результат POST неизвестен из-за сетевого обрыва после отправки, не делать слепой повтор, способный опубликовать дубликат; явно сохранять/логировать неопределённый исход без секретов.
- Описать подключение и настройку `@SCRTRY`, OAuth scopes, защищённое хранилище refresh token, owner user ID, согласие/opt-out, обработку удаления контента, платные API credits и известные ограничения в документации/runbook проекта.
- Проверить соблюдение Developer Agreement/Policy и Automation Rules X. Любая реальная AI-generated reply activity, включая live test reply, запрещена до получения письменного явного одобрения X; локальные проверки с fake transport разрешены. Включение реальных ответов требует отдельного явного конфигурационного подтверждения письменного одобрения X и проверки setup аккаунта. Перед запуском владелец должен включить `Automated` label на аккаунте, указать оператора в bio и связать аккаунт с человеческим аккаунтом. Наличие API credentials само по себе не разрешает реальную публикацию.

## Критерии приёмки

- [ ] Без явного enable и валидных credentials X adapter не запускается и не меняет поведение других каналов. Отсутствующие/ошибочные значения дают безопасную диагностическую ошибку без вывода токена.
- [ ] Если `Addressed reply v1` выключен или точный origin link отсутствует, публикация безопасно отклоняется без fallback на legacy/последний event.
- [ ] Запуск с настроенными credentials опрашивает user mention timeline; cursor/pagination обрабатывают записи, доступные в окне X. Выход cursor за предел 800 mentions явно регистрирует gap/health warning и сообщает владельцу; недоступные записи не объявляются восстановленными.
- [ ] Подтверждённое упоминание `@SCRTRY` от разрешённого owner X ID один раз попадает в общую Personal Conversation; чужой автор, собственный пост Secretary, отсутствие адресного mention или неподдерживаемый тип не попадают в неё.
- [ ] Секреты OAuth не записываются в логи, event payload или adapter state. Refresh token хранится отдельно с правами `0600`; обновлённый token сохраняется, и refresh → restart → authenticated request проходит без повторного входа, если выдан `offline.access`.
- [ ] Реальная публикация AI replies по умолчанию выключена и требует отдельного явного конфигурационного подтверждения письменного одобрения X и проверки setup аккаунта. Runbook требует включённый `Automated` label, указание оператора в bio и ссылку на человеческий аккаунт. До подтверждения разрешены только локальные проверки с fake transport; никакие реальные AI reply posts, в том числе тестовые, не отправляются.
- [ ] X-origin turn не получает приватную историю из других Channel adapters, private Workspace или локальные секреты. В MVP Worker для X turn не запускается; это проверяется на уровне маршрутизации, потому что его инструменты имеют доступ к локальному Workspace. Regression использует sentinel из приватного Telegram/Web сообщения и подтверждает, что его нет в public model context или опубликованном reply. Запрос, требующий private material, направляется владельцу в приватный канал.
- [ ] На один interaction публикуется максимум один финальный Secretary reply в ветку исходного X post через `Addressed reply v1`; нет отдельного acknowledgement, серии частей или unsolicited third-party mentions. Другие каналы не зеркалятся.
- [ ] Owner получает ясное описание публичной автоматизации и может отправить `STOP`; это немедленно отключает будущие автоответы и переживает restart. `START` включает их снова; другие авторы не меняют состояние.
- [ ] Удаление/изменение исходного или созданного X post, переход в protected/private, suspension или withholding прекращает использование контента и отражается во всех Secretary-owned durable копиях. Полученный прямой запрос X/владельца на удаление немедленно ставится в очередь очистки; все копии очищены не позднее 24 часов с получения запроса. Проверка подтверждает tombstone/обновлённый текст в Conversation entries и transcripts/checkpoints.
- [ ] Изолированные события Web/Telegram и не связанные с X-вводом Worker events не публикуются в аккаунт `@SCRTRY`.
- [ ] Restart/replay, повтор одного mention, повтор event delivery и повтор запроса транспорта не создают дубль входного Conversation entry или повторную публикацию. Неопределённый результат POST после сетевого сбоя остаётся видимым оператору и не retry-ится вслепую.
- [ ] Unicode, пустой текст после удаления адресного mention, вложения без текста, удалённый/недоступный исходный пост, rate limit, OAuth expiry и ошибки API обрабатываются без потери cursor или утечки секретов.
- [ ] Длинный результат не усечён молча и не публикуется несколькими posts; пользователь получает ровно один короткий reply с просьбой запросить сокращение.
- [ ] Автоматические проверки используют fake HTTP transport и не требуют реального X аккаунта/кредитов. Без live-reply gate сетевой транспорт не публикует AI replies. `go test ./internal/xchannel ./cmd/secretaryd ./internal/webapi -count=1` и весь `go test ./...` проходят.
- [ ] Документация показывает переменные конфигурации, настройку developer app и owner allowlist, ориентир текущей оплаты read/write и способ безопасно проверить настоящий mention. Live acceptance с аккаунтом владельца выполняется только после policy gate и сохраняет ссылку на тестовую ветку без секретов.

## Comments

- Текущий контракт считает Channel adapter клиентом общей Personal Conversation. `@SCRTRY` не должен становиться второй Secretary identity.
- Исследование от 2026-10-12 проверяет публичные X docs. Текущие тарифы меняются; владелец должен проверить расчёт перед включением polling.
- Ответ X публичен по самому формату упоминаний. Входные посты с других X-аккаунтов запрещены до реализации явного account linking и изоляции Conversation.
- X Automation Rules требуют opt-in/opt-out, максимум одного автоответа на interaction и запрещают публичную публикацию личной/закрытой информации. Публичный context изолируется от приватных данных общей Personal Conversation; удаление/редактирование X Content синхронизируется.
- В Developer Guidelines X отмечено, что AI-powered replies требуют предварительного письменного явного одобрения. До него запрещены любые реальные AI reply posts, включая тестовые. Перед запуском владелец также включает `Automated` label, указывает оператора в bio и связывает аккаунт с человеческим аккаунтом.
