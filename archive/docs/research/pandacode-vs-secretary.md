# PandaCode и Secretary

Проверено 20 октября 2026 года. Источники: README, документация, исходники и последний GitHub release [aicodeking/pandacode](https://github.com/aicodeking/pandacode); для Secretary — [README](../../README.md), [GLOSSARY](../../GLOSSARY.md), [runtime contracts](../architecture/runtime-contracts.md) и [ADR](../adr/).

## Зафиксированные факты

- **PandaCode — desktop workspace для coding agents.** Нативное приложение на Tauri/Rust/SQLite объединяет проекты, Git, терминал и браузер; запускает установленные CLI/ACP harnesses, среди которых Claude Code, Codex, Kimi Code, OpenCode, Antigravity и Grok Build. Выбор harness и модели делается для задачи. См. [README](https://github.com/aicodeking/pandacode#pandacode) и [provider docs](https://github.com/aicodeking/pandacode/blob/main/docs/providers.md).
- **У PandaCode есть сохраняемые задачи и команды.** История разговора и provider session ID переживают перезапуск приложения; процессы агентов запускаются на активный turn. Команда состоит из architect и до трёх workers, которые могут использовать разные harnesses. См. [README](https://github.com/aicodeking/pandacode#features), [architect/worker docs](https://github.com/aicodeking/pandacode/blob/main/docs/architect-workers.md) и [provider docs](https://github.com/aicodeking/pandacode/blob/main/docs/providers.md).
- **Боты PandaCode работают через каналы.** Бот использует обычные PandaCode tasks как разговоры, отдельную привязку внешнего channel thread к task, память, расписания и правила одобрения. Документация называет Telegram, Slack, Discord, WhatsApp и локальный web chat; канальные credentials хранятся в системном secure store. См. [bots docs](https://github.com/aicodeking/pandacode/blob/main/docs/bots.md).
- **Исполнение у PandaCode может быть локальным или изолированным.** README перечисляет локальные VM на Tart и sandbox-провайдеров Daytona, Cloudflare и AWS; также поддерживаются task worktrees с guard-ами при удалении. Уровни разрешений включают `ask`, `auto`, `plan` и `full`, с отображением на политику конкретного harness. См. [README](https://github.com/aicodeking/pandacode#features), [worktrees docs](https://github.com/aicodeking/pandacode/blob/main/docs/worktrees.md) и [IPC contract](https://github.com/aicodeking/pandacode/blob/main/docs/ipc.md).
- **PandaCode хранит состояние локально.** README заявляет отсутствие учётных записей, аналитики и телеметрии; проекты, разговоры и настройки хранятся в SQLite на устройстве. При этом приложение выполняет периодические публичные запросы обновлений и метаданных цен; prompts идут выбранному пользователем CLI/provider. Это описание проекта, а не независимый аудит сетевого поведения. См. [README: Privacy и Data](https://github.com/aicodeking/pandacode#privacy).
- **Secretary — серверный владелец общей переписки и жизненного цикла задач.** Personal Conversation, Task, Worker binding и Result принадлежат серверу и не зависят от channel adapter или execution node. Web/PWA и Telegram проецируют одну упорядоченную переписку; отдельные Worker остаются адресуемыми между попытками и закрываются явно. См. [GLOSSARY](../../GLOSSARY.md), [runtime contracts](../architecture/runtime-contracts.md), [ADR-0001](../adr/0001-one-conversation-and-worker-lifecycle.md) и [ADR-0005](../adr/0005-channel-projections-and-owner-identity.md).
- **У Secretary другой execution-контракт.** Сервер направляет persistent Worker на локальный или подключённый execution node по исходящему соединению; сервер владеет Task/Worker lifecycle, маршрутизацией Result и выбором node, а native harness выполняет работу. Документированное направление Public v1 требует Codex и Claude Code и задаёт full-access как единственный обещанный режим; Secretary не проектирует собственную approval engine или обязательную sandbox-систему. См. [runtime contracts](../architecture/runtime-contracts.md), [ADR-0002](../adr/0002-native-harnesses-and-execution-authority.md) и [ADR-0004](../adr/0004-two-product-offerings.md). ADR фиксируют направление продукта, и могут опережать реализацию.

## Сравнение и вывод

Пересечение существенное: оба проекта сохраняют разговоры и задачи, поддерживают несколько harnesses, прямое управление текущей работой, каналы общения и параллельную работу. У PandaCode команды — architect с workers; у Secretary параллельно живут отдельные Workers, без server-managed дерева дочерних агентов. PandaCode уже соединяет desktop coding workspace с ботами и каналами; Secretary не следует описывать как продукт без bot/channel интерфейса. См. [PandaCode README](https://github.com/aicodeking/pandacode#features), [PandaCode teams](https://github.com/aicodeking/pandacode/blob/main/docs/architect-workers.md) и [ADR-0001](../adr/0001-one-conversation-and-worker-lifecycle.md).

Главное различие — **центр продукта и граница состояния**. PandaCode организован вокруг локального desktop workspace и coding tasks; его bot conversation тоже является task в этом workspace. Secretary организован вокруг одной серверной Personal Conversation, а задачи — это persistent Workers, которые можно продолжить через другой канал или execution node. PandaCode подчёркивает локальное управление проектом, team orchestration, Git/worktrees и выбор среды исполнения; Secretary — общую долговременную беседу, server-owned lifecycle и перенос выполнения между хостами.

**Практический смысл:** PandaCode ближе к полноценному рабочему столу для разработки и локальных/облачных coding agents; Secretary ближе к постоянному личному ассистенту, который связывает беседу и продолжение поручений между клиентами и машинами. Это сравнение заявленных интерфейсов и контрактов из документации, не результат установки или тестирования приложений.
