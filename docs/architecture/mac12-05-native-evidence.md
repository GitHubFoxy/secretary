# MAC12-05 native Codex command evidence

The original Codex 0.163.0 transcript contains a native event_msg/item_completed with item.type=CommandExecution, item.id=exec-3c90708a-1303-40bf-837a-4ba931ae5b68, status=failed, exit_code=7, source=unified_exec_startup. The failing command executed once. Its native session ID matches the worker session identified by the acceptance report. The outer code-mode exec result text is not used as evidence.

In agentclientprotocol/codex-acp v2.2.2, src/tool-calls/reporters/CommandReporter.ts exports this as ACP tool_call/tool_call_update using the native toolCallId. src/ToolCallName.ts maps unifiedExecStartup to exec_command. src/tool-calls/AcpToolCallRenderer.ts emits terminal exit in update._meta.terminal_exit = {exit_code,signal,terminal_id}; for nonterminal commands it uses rawOutput.exit_code. Native status comes from the same command item. These values are not model-produced stdout, and the corresponding invocation ID remains stable through the ACP tool tracker.

Secretary's internal/node/acp_runtime.go already routes events to acpToolTracker.observe and emits ActivityToolResult. MAC12-05 now records nonzero typed command exits during a Codex Attempt, keyed by native toolCallId. The success-only final classification fails unrecovered command exits with tool_execution_failed, while preserving provider failure, cancellation and authoritative CompletionEvidence. Duplicate terminal tool updates are consumed once by acpToolTracker. For explicit same-Attempt recovery, a strict terminal structured claim includes exactly the observed failed IDs in recovered_tool_use_ids; the user-visible message preceding the structured claim remains ordinary text. A subsequent successful command alone does not clear the failure. A plain JSON stdout object cannot set exit status.

This approach does not disable Code Mode or change global Codex configuration; selected models can remain code_mode_only. Native CommandExecution is emitted by Codex itself even for nested code-mode tools. The ACP command-reporting contract supplies tool identity and result status without requiring a parent outer exec ID for the currently active native session/turn.
