## Что отправляется

Specialist дополнительно получает `specialists.md`, если он существует. Это размер описаний, не измерение токенизатором. Другие подключённые MCP и встроенные инструменты harness не включены.
- Память `~/.secretary/memory/*.md` не вставляется автоматически: промпт предлагает читать её по необходимости. Skills синхронизируются в `.claude/skills` и `.agents/skills` (`server/skills.ts`), их видимость и загрузку определяет harness; на Host в Secretary-хранилище один `day-summary` размером 2 731 байт. Нельзя считать, что весь skill вставляется в каждый ход; глобальные и проектные skills и инструкции могут увеличивать контекст.
- `server/session.ts:next`, `server/chat.ts:chatTranscript`: при отсутствии `harness_session_id` в начало сообщения добавляются последние user/agent/report до 100 000 JS-символов, обрезка только по границе сообщения. Оценка комментария кода ~30k токенов приблизительная; для русского и разных токенизаторов коэффициент не гарантирован. При resume транскрипт повторно приложением не вставляется, но harness продолжает контекст. Смена harness сбрасывает идентификатор; новый запуск без id тоже может получить историю. Не все новые сессии имеют историю.
- `list` возвращает все видимые доступные сессии соответствующего уровня и модели со всеми уровнями reasoning, без пагинации (`server/mcp.ts`). На срезе у Secretary 3 видимых Specialist: строки SQLite в JSON — 954 байта, списки моделей Claude 355 и Codex 779 байт; вместе минимум около 2,1 КБ до обёрток и дополнительных полей `sessions.list()`. 83 сессии всего, не все входят в этот ответ. Модели запрашиваются при каждом вызове. `read` по умолчанию отдаёт 10 полных сообщений, максимум 100; `raw:true` — сырые события без ограничения размера каждого. Время/деньги конкретных вызовов отдельно база надёжно не атрибутирует.
- Финальный ответ Worker целиком становится `[report #…]` во входе родителя (`server/sessions.ts`, `server/chat.ts`). Промежуточный отчёт вызывает полноценный ход родителя; `NO_REPLY` скрывает вывод и останавливает дальнейшую пересылку, но не устраняет обработку.

Это суммарные входы всех вызовов модели, а не размер окна контекста; один ход может вызвать модель много раз. ## Кэш и стабильность префикса

Встроенные строки и порядок `toolsFor` фиксированы кодом, но зависят от роли и порядка списка harness; инструкции и внешние MCP меняются при изменении файлов/конфигурации. Дата явно в `persona.ts` не подставляется, однако harness может добавлять свою дату или окружение. `server/sessions.ts` генерирует случайный bearer token на создание объекта сессии; `claude.ts` и `codex.ts` передают его в MCP-конфигурацию, а для внешних секретов генерируют случайные имена переменных окружения. Доказательств, что эти значения попадают в промпт модели и ломают кэш, нет: нужна трассировка фактического запроса с маскированием секретов. Resume сохраняет историю harness, но не гарантирует попадание в кэш: TTL, изменение модели/инструментов, компакция и внешние инструкции тоже влияют. Доля cache read выше — измеренный показатель, а не доказательство неизменности префикса между ходами.
