# Команды и ссылки в композере (#123)

Owner должен выбирать skills и `/compact`, а также ссылаться на файлы и Session без запоминания путей и идентификаторов. Подсказки должны работать с клавиатурой и на телефоне.

## Что есть сейчас

`web/src/components/Composer.svelte` хранит текст в `textarea`, Enter на ПК отправляет сообщение, а на сенсорном устройстве переносит строку. `server/index.ts:51` обрабатывает команды WebSocket; `send` передаёт текст и вложения в Session. Очередь сохраняется до отправки (`server/queue.ts`). `server/codex.ts:44` возобновляет thread и отправляет текст через `turn/start`. `server/models.ts:31` запускает Claude Code для `initialize`, а `server/chat.ts` преобразует события harness в чат. Доступ к MCP есть у Secretary Agent, но не у Worker; ссылку на Session нельзя выдавать за гарантию доступа к `read`/`send`.

## Проверка harness и пример T3 Code

В пустой временной папке Claude Code со stream-json `initialize` вернул `response.commands` с `name`, `description`, `argumentHint`; отдельного поля `skills` не было. Список зависит от cwd и окружения, поэтому общий кэш по harness, как для моделей, неверен. Отправка `/compact` как user-сообщения распозналась как локальная команда и вернула `local_command_outcome.kind=failed` и `No messages to compact` для пустой истории. Успешное сжатие и его события ещё нужно проверить на непустой тестовой Session.

В той же изоляции `codex app-server` версии 0.171.0 ответил на `skills/list` с `cwds` списком `skills`, включая `name`, `path`, `enabled`, и принял метод `thread/compact/start`: для заведомо неверного threadId вернул ошибку проверки ID. Это подтверждает наличие метода, но не успешное сжатие. В текущем `server/protocol/` есть тип `UserInput` с `skill`, но определения запросов отсутствуют; протокол следует обновить генератором, не вручную. `prompts/list` не подтверждён как источник skills.

T3 Code запрашивает skills через `skills/list` по cwd (`apps/server/src/provider/CodexProvider.ts:773`), запускает `thread/compact/start` (`apps/server/src/orchestration-v2/Adapters/CodexAdapterV2.ts:8629`), разделяет типы подсказок в `apps/web/src/composer-logic.ts:28`. Его редактор сложнее textarea Secretary; переносить его целиком не требуется.

## Варианты

1. **Нативные источники и явные действия**: Claude `initialize`, Codex `skills/list`, отдельный серверный compact. Средний объём; источником истины остаётся harness, но потребуется обработка ошибок, состояния и обновление списка.
2. Сканировать папки skills и отправлять `/compact` текстом обоим harness. Меньше кода на старте, но правила обнаружения различаются, а Codex требует RPC; вариант не выполняет критерии.
3. Перенести редактор T3 Code. Даёт богатые ссылки, но значительно увеличивает объём и зависимости.

Рекомендация: вариант 1, простой список над textarea и явная модель ссылок. `/compact` выполнять только отдельно от обычного текста и вложений, когда Session свободна; не прерывать ход молча. Для работающей Session показать причину недоступности. Обновлять список по открытию меню или после смены Session, с коротким кэшем по harness и cwd; ошибки показывать, а не подменять пустым списком.

## Шаги реализации

1. В изолированной временной папке создать непустую Session каждого harness, выполнить compact, записать успешные события и ошибки, проверить resume после него. Для Codex дождаться завершения, а не считать RPC-ответ завершением. Проверить запуск skill Claude через `/name`, Codex через `UserInput.skill` с настоящим путём и параметры обычного текста. Это обязательный протоколный spike до реализации: текущие эксперименты успешное сжатие не доказывают.
2. Добавить запрос списка команд для текущей Session в `server/index.ts` и загрузчики рядом с адаптерами: Claude `initialize` с cwd Session, Codex `skills/list` с cwd и фильтром `enabled`; вернуть имя, описание и необходимый path. Проверить одинаковые имена, ошибки harness, смену cwd и устаревший ответ. Не выставлять произвольные команды Claude как skills без проверки их исполнимости.
3. В `Session` и адаптерах добавить явное действие compact с проверкой статуса, resume ID, ошибками и завершением; не посылать его через обычный `turn/start` Codex. Сохранить событие успешного сжатия в истории и преобразовать в `server/chat.ts` в разделитель «Контекст сжат» со временем и доступными измерениями. Согласовать формат с #134 и использовать тот же путь для автоматического сжатия, без двойного разделителя. Проверить пустую Session, ошибку, повторную загрузку и running.
4. Добавить ограниченный поиск файлов в папке Session на Host: ограничить число результатов, не выходить за границу через `..` и symlink, не загружать содержимое файлов в браузер. Определить политику скрытых и игнорируемых файлов по существующим соглашениям проекта. Список Specialists/Workers брать из Sessions; вставлять стабильный ID и достаточно явный текст, чтобы harness понял ссылку. Сохранять метаданные ссылки в истории, чтобы переход открывал нужную Session и не зависел от переименования. Уточнить права MCP для каждой роли и не обещать Worker доступ к нему.
5. В `Composer.svelte` показывать меню над полем: `/` только в начале сообщения, `@` у курсора; фильтрация, стрелки, Enter для выбора до обычной отправки, Escape, тап, возврат фокуса и корректная замена диапазона при редактировании в середине текста. Учитывать IME, множественные ссылки, пробелы в путях, отсутствие результатов, смену Session и запоздавшие ответы. Для Codex передавать выбранный skill структурированно, проверив совместимость очереди и истории; для Claude — проверенный синтаксис вызова.
6. Тестировать наблюдаемое поведение: запросы и ограничения поиска, сериализацию очереди и перезапуск, успешное/ошибочное сжатие и разделитель, ссылки после переименования, клавиатуру и касание. Запустить `bun test` в `server/` и `web/`, затем изолированный экземпляр приложения: проверить оба harness, реальное сжатие и выбор на ПК и телефоне. Не перезапускать рабочую службу.

## Открытые вопросы

- Как хранить ссылки и структурированный вызов skill в очереди и истории без потери при редактировании текста: определить после проверки существующей схемы и протокола.
- Формат успешных событий compact и точная семантика запуска skill требуют практической проверки из шага 1. До неё оценка и детали реализации предварительны.
