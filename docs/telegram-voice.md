# Голосовые сообщения Telegram

Основная конфигурация Secretary остаётся `config.toml`. Настройки распознавания читаются из отдельного `config.yaml` рядом с ней: скопируйте `config.example.yaml`, укажите доступные веса Parakeet Q8 и положите рядом `formatter.md` из этой папки. Относительные пути к весам и промпту разрешаются от папки конфигурации.

На сервере необходимы `ffmpeg`, `ffprobe` (для аудио без заявленной длительности) и `nemo-speech` (в PATH; на omarchy используется существующий `/home/coder/.local/bin/nemo-speech`). Для форматирования используется установленный Codex CLI и существующая подписочная авторизация (`codex login`), `provider: codex`; API-ключи не нужны и не используются. Путь к CLI берётся из `SECRETARY_CODEX_COMMAND`, затем `CODEX_PATH`, затем PATH. Отказ подписочной авторизации не блокирует ASR: используется исходный текст с уведомлением. Старое поле `api_key_env` отклоняется.

После изменений YAML/промпта перезапустите Secretary: Telegram adapter использует настройки, загруженные при старте. `formatter.enabled: false` отключает облачное форматирование; `show_asr_in_chat: true` показывает итоговый текст ответом на исходное voice. По умолчанию отдельная расшифровка не публикуется.

Поддерживаются Telegram voice, audio и аудиодокументы с распознаваемыми типами `.oga`, `.ogg`, `.opus`, `.mp3`, `.m4a`, `.mp4`, `.wav`, `.flac`, `.webm`, `.aac`, локальный `nemo-speech` CPU с выбранным Parakeet GGUF и форматтер Codex по подписке. До download проверяются владелец/topic и известные лимиты; фактические размер и decoded WAV-длительность также ограничены. При отсутствии Telegram `duration` оригинал сохраняется, затем `ffprobe` определяет фактическую длительность до ASR: значение выше лимита, повреждённое или неопределённое аудио не передаётся в ASR; оригинал остаётся со статусом `failed`. Voice и text сохраняют порядок внутри topic, другие topics обрабатываются независимо. Одновременно запускается один ASR.

Оригинальные байты аудио сохраняются в центральном Server Artifact Store до запуска ASR. После успешного распознавания создаётся связанный Markdown Artifact, содержащий итоговую расшифровку, ссылку на оригинал и, если форматтер изменил текст, исходный ASR. В Telegram state дополнительно сохраняются серверные идентификаторы обоих Artifacts, raw, успешный formatted и исходная Telegram identity. Результирующее сообщение для Secretary или Worker содержит текст, `artifact://` ссылку на транскрипт и `artifact://` ссылку на оригинал. Авторизованная Execution Node скачивает оба Artifact по ID через существующий Server API, в том числе после перезапуска или переподключения. Применяются меньший из настроенного лимита ASR и лимита Artifact Store в 8 МиБ. При ошибке ASR оригинал сохраняется со статусом обработки `failed`, ссылка на несуществующий транскрипт не создаётся.

Форматтер запускает GPT-6 Luna none в Codex CLI; получает инструкции через временный `model_instructions_file`, transcript только через stdin JSON. API-key env не передаётся, login принудительно ChatGPT. Аудио не передаётся облачному форматтеру. Пользовательский config/rules и project docs отключены; отдельный cwd и ephemeral запуск не используют историю. CLI execution/integration features отключены, sandbox read-only, неожиданные tool/action/reasoning events отклоняют результат. Ошибка ASR сообщает о неудаче и освобождает очередь; ошибка/невалидный результат форматтера возвращает raw.

Проверка сохранности текста консервативная и не гарантирует полной смысловой эквивалентности. Тайм-ауты — ограничения ожидания, не обещание скорости. ENV threads=2 не является жёстким ограничением CPU/RAM; при необходимости администратор ограничивает сервис средствами systemd.

В приватном Telegram state у новых успешных расшифровок сохраняется объект `timing`: `download_ms`, `asr_ms`, `formatter_ms`, `processing_ms` и `formatter_status` (`disabled`, `succeeded`, `failed`, `unavailable`). Значения — миллисекунды монотонного wall clock. Download включает getFile и скачивание. ASR включает ожидание локального слота, ffmpeg, загрузку модели и inference. Formatter измеряет весь вызов Codex, включая запуск CLI. `processing_ms` завершается до сохранения/уведомлений Telegram и передачи текста агенту; время агента и ответа Telegram не входит. При отключённом или отсутствующем форматтере его время 0. Replay сохраняет первоначальные метрики. Старые расшифровки без объекта `timing` продолжают читаться.

В журнал пишутся только numeric update/message ID, длительности и фиксированные статусы; transcript, audio, file ID и детали ошибок не логируются. При ошибке download/ASR длительности остаются в журнале, transcript не создаётся. Ошибка форматтера измеряется и сохраняется вместе с raw fallback. Новых сообщений в чат и конфигурационных флагов для таймингов нет.

Если Telegram не смог доставить уведомление об ошибке ASR или проверки длительности, терминальный результат обработки уже записан в приватное состояние адаптера; после перезапуска повторяется только сообщение об ошибке и идемпотентное подтверждение статуса в Server. Скачивание и повторный ASR для этого update не запускаются.
