# Secretary v2: договорённости и открытые вопросы

> Журнал обсуждений. Актуальные решения — в [adr/](adr/) и [GLOSSARY.md](../GLOSSARY.md). Термины и цифры ниже не переписываются: здесь «владелец» может означать продавца, а «Chief of agents» — Secretary Agent.

Обсуждение 15 ноября 2026 года. Документ фиксирует решения владельца и вопросы, на которые ещё нет ответа. Код по этому документу пока не пишется.

Итоговая архитектура фазы 1 — в [architecture.md](architecture.md).

## Почему переделка

Старый Secretary написан на Go (его документация сохранена в git-теге `go-archive`, папка `archive/`): около 58 тыс. строк рабочего кода и 80 тыс. строк тестов, 2500 коммитов. До релиза он не дошёл. Путь до первого разговора тяжёлый: нужно ставить серверы, создавать Telegram-бота и разбираться в harness.

Go не подходит под новый сценарий. У человека может быть только телефон, а клиент (PWA, Capacitor) и облачная часть (Cloudflare) пишутся на TypeScript. Один язык на весь стек проще.

## Решения

### Клиент

- Android-приложение: PWA + Capacitor + небольшой мост на Kotlin для API телефона.
- Секретарь открывается долгим нажатием Power. Для этого нужен `VoiceInteractionService` в нативной части; одна PWA эту роль получить не может.
- Голос: распознавание речи (STT) и синтез (TTS). Speech-to-speech модели не используются.
- Telegram не нужен.

### Модель и подписки

- Как в T3 Code и MausBot: пользователь входит своей подпиской, а работа идёт внутри нативного harness — Codex или Claude Code. Своей модели и своих ключей у продукта нет.
- Нужна быстрая смена модели.
  - Внутри одного harness модель меняется между ходами, контекст сессии сохраняется.
  - Переход между harness (Codex ↔ Claude) создаёт новую сессию. Контекст переносится через общую память и сводку при передаче.

### Где работает harness

Codex и Claude Code — программы для командной строки, им нужен Linux. Поддерживаются два варианта:

1. **Свой сервер пользователя.** У владельца это omarchy.
2. **Облачный контейнер на пользователя.** Пользователь входит своей подпиской внутри своего контейнера.

Вариант «harness прямо на телефоне» отвергнут.

### Права агентов

На старте все агенты работают с полным доступом (full access, YOLO), без подтверждений. Ограничения добавим позже.

### Деньги

Окончательная схема будет позже. Рабочая идея: пользователь платит владельцу около $10 в месяц, а контейнер оплачивает сам по факту использования.

### Роли агентов

- **Chief of agents (секретарь)** — одна постоянная сессия harness, с которой пользователь всегда разговаривает. Раздаёт задачи другим сессиям.
- **Chief of project** — главный агент отдельного проекта, своя постоянная сессия.

### Память

Один внешний слой памяти, общий для всех harness, моделей и подписок.

Кандидат — [Hindsight](https://github.com/vectorize-io/hindsight) (MIT, self-host, MCP и plugin с `SKILL.md`). Подробности в `~/personal/Karpathy Wikis/synthesis/Portable personal agent memory and learned workflows.md`:

- harness подключаются к памяти через MCP, правила работы описаны в `SKILL.md`;
- память делится на области: пользователь, бот, проект;
- навыки хранятся отдельно как версионированные `SKILL.md`;
- Obsidian не используется как рабочая память агента;
- выбор нужно подтвердить прототипом.

### Бенчмарк-сценарий: диктант

У пользователя есть текст. Секретарь диктует его по словам, как в школе, а пользователь пишет от руки. Сценарий проверяет голосовой цикл целиком.

## Ограничения и риски

### Правила подписок (на ноябрь 2026)

- **ChatGPT / Codex.** С 29 сентября 2026 года OpenAI официально разрешает использовать подписку в сторонних приложениях («Sign in with ChatGPT»). Хостинговым продуктам нужно подать заявку. Запуск `codex login` в своей среде допустим.
- **Claude.** Anthropic запрещает использовать OAuth-токены подписок Free, Pro и Max в сторонних продуктах, включая Agent SDK, без предварительного одобрения. Если владелец сам запускает Claude Code на своём сервере, всё в порядке. Контейнер с Claude Code, который продукт размещает для других людей, — серая зона.
- **Предложение:** в облачных контейнерах начать с Codex. Claude поддерживать там, где пользователь сам запускает harness на своём сервере. Перед запуском перепроверить официальные условия.

### Скорость голоса

Секретарь — сессия harness, поэтому первый ответ голосом приходит примерно через 1–3 секунды. Владелец с этим согласен.

### Стоимость памяти

Hindsight вызывает LLM, чтобы извлекать факты (retain) и делать выводы (reflect). Подписка для этого не подходит, нужен API-ключ дешёвой модели или локальная модель. Это отдельный небольшой расход. Требование LLM-ключа нужно перепроверить по документации Hindsight.

### Cloudflare

- **Workers** — функции без состояния: HTTP и маршрутизация.
- **Durable Objects** — объект с постоянной идентичностью, собственной SQLite, WebSocket с hibernation и будильниками (alarms).
- Codex и Claude Code внутри Worker или Durable Object не запускаются. Для них нужен сервер или контейнер.

## Память и навыки: как это сделано в Hermes Agent

Проверено по исходникам и документации Hermes в `~/.hermes/hermes-agent` (коммит `2bd378ed1b`, 5 ноября 2026).

### Три слоя памяти

1. **Маленький профиль, всегда в контексте.** `MEMORY.md` (2200 знаков: окружение, договорённости, сделанная работа) и `USER.md` (1375 знаков: предпочтения пользователя). Агент сам добавляет, правит и удаляет записи инструментом `memory`. При переполнении инструмент возвращает ошибку, и агент сам сжимает старые записи. Оба файла попадают в системный промпт замороженным снимком в начале сессии, поэтому новая запись действует со следующей сессии.
2. **Поиск по всей истории.** Все сессии лежат в SQLite с полнотекстовым поиском FTS5. Инструмент `session_search` возвращает настоящие сообщения без пересказа моделью. Запрос занимает около 20 мс и ничего не стоит.
3. **Внешний провайдер, по желанию.** Hindsight, Honcho, Mem0 и другие подключаются плагином и работают рядом со встроенной памятью, а не вместо неё.

Hermes прямо говорит, что память работает только при границах сессий. Если разговор идёт неделями одной сессией, цикл «забыл → вспомнил из памяти → нашёл в истории» почти не срабатывает.

### Как улучшаются навыки

- **Навык** — это `SKILL.md`: порядок шагов, рабочие команды, ловушки с причиной, предпочтения пользователя к результату. Агент создаёт и правит навыки инструментом `skill_manage`.
- **Фоновое ревью после хода.** Hermes запускает копию агента с той же моделью и тем же разговором. Копия отвечает на вопрос: «Что сохранить в память и какие навыки поправить?» У неё есть только инструменты памяти, навыков и чтения файлов. Основной разговор она не трогает.
  - Ревью памяти запускается раз в 10 ходов (`memory.nudge_interval`).
  - Сигналы для навыков: пользователь поправил стиль или порядок работы, нашёлся нетривиальный приём, загруженный навык оказался неверным.
  - Порядок действий: поправить загруженный навык → поправить общий навык класса → добавить файл в `references/` → только потом создать новый навык.
  - Не сохраняются: сбои окружения, утверждения «инструмент X не работает», разовые задачи, неудавшиеся попытки.
- **Ручная команда `/learn`.** Превращает в навык процесс из текущего разговора, документацию или заметки.
- **Curator** — обслуживание раз в 7 дней в простое. Неиспользуемые навыки становятся `stale` через 14 дней и архивируются через 30. Объединение похожих навыков моделью выключено по умолчанию. Навыки никогда не удаляются, перед изменениями делается снимок с возможностью отката.
- **Контроль.** `write_approval` ставит записи в очередь на подтверждение. Навык можно закрепить (pin) или запретить менять (lock). Есть журнал изменений и `/journey` — хронология того, чему агент научился.

### Что это значит для Secretary

Hermes владеет циклом агента, поэтому может запустить свою копию после хода. Мы используем Codex и Claude Code и их цикл не контролируем. Но схему можно повторить снаружи:

- профиль подаётся в начале сессии через `AGENTS.md` / `CLAUDE.md` или первое сообщение;
- история всех сессий хранится у нас, поиск по ней даётся через MCP;
- навыки лежат в одной папке, подключённой и к Codex, и к Claude Code: оба harness понимают `SKILL.md`;
- ревью после сессии — отдельный короткий запуск harness по подписке пользователя: он получает разговор и права только на память и навыки. API-ключ не нужен.

Hindsight в такой схеме не обязателен для первой версии. В отличие от ревью через harness, ему нужен отдельный API-ключ к модели.

### Решения и находки от 15 ноября (продолжение)

- **Обязательны нативный Claude Code по подписке и Codex.** Другие harness — позже.
- **Ценность Hermes для владельца — в памяти**: Hermes «знает и помнит». Самоулучшение всех навыков подряд владелец считает малополезным.
- **Данные это подтверждают.** В [SkillsBench](https://arxiv.org/html/2602.12670v4) навыки, которые модель пишет сама до решения задачи, в среднем не помогают, а в версии v4 даже ухудшают результат на 8–11 п.п. Навыки, проверенные людьми, добавляют 16–25 п.п. Работы [SkillEvolver](https://arxiv.org/pdf/2605.10500) и [reSolve](https://arxiv.org/pdf/2608.28638) показывают пользу навыков, которые уточняются по реальной обратной связи. Вывод: навык меняется только по реальному сигналу — поправке владельца или проверенному успеху. Не после каждого хода.
- **В Hermes уже есть Codex App-Server Runtime.** Hermes становится оболочкой вокруг Codex: инструменты и песочница — от Codex, сессии, память, ревью навыков и gateway — от Hermes. Работает по подписке ChatGPT. Такого же режима для Claude Code в Hermes нет.

- **Миграция из Hermes (желательно).** Когда проект Secretary будет создан, хорошо бы перенести в него данные из Hermes на omarchy: `~/.hermes/memories/USER.md` и `MEMORY.md`, историю сессий из `~/.hermes/state.db` и полезные навыки из `~/.hermes/skills/`. Тогда секретарь с первого дня знает владельца. Что переносить и в каком виде, решим, когда появится формат памяти Secretary.

- **Чья память (решено).** У Secretary Agent и каждого Specialist своя память. Плюс небольшой общий профиль владельца, который видят все, а пишет только Secretary Agent. Specialist сообщает замеченные предпочтения владельца в отчёте, и Secretary Agent решает, вносить ли их в профиль.

2. Ревью навыков: автоматически после каждой сессии или по команде вроде `/learn`? Подтверждать изменения навыков?

## Хостинг: локально и облако (решено 15 ноября)

Одна программа Secretary и один Docker-образ. Программа живёт рядом с harness и хранит состояние на своём диске: `~/.secretary`, `~/.codex`, `~/.claude`, SQLite.

```
ЛОКАЛЬНО (свой сервер / VPS)
Телефон/сайт ──► сервер пользователя
                 └─ программа Secretary (работает всегда)
                    ├─ claude / codex
                    └─ состояние на диске

ОБЛАКО (Cloudflare)
Телефон/сайт ──► Worker (вход, поиск контейнера, пробуждение)
                 └─► контейнер пользователя
                     └─ та же программа Secretary
                        ├─ claude / codex
                        └─ состояние: при старте из R2, перед сном в R2
```

Облачный путь — это локальный плюс три небольшие детали снаружи основной логики:

1. **Вход и пробуждение.** Worker + Durable Object: проверить пользователя, найти и разбудить его контейнер, проксировать запрос. Локально клиент ходит на сервер напрямую (Tailscale или Cloudflare Tunnel).
2. **Хранение состояния.** Перед сном программа упаковывает состояние в tar и кладёт в R2, при старте достаёт. Снимки Cloudflare не используем: они в бете, требуют ручного создания и истекают через 30 дней. Бэкап в R2 заодно позволяет сменить провайдера.
3. **Не засыпать во время работы.** Пока идёт фоновая задача, программа сообщает платформе, что занята.

Клиент один и тот же, различается только адрес: сервер пользователя или Worker.

**Порядок:** программа на omarchy в Docker (фаза 1) → три детали для облака. При смене провайдера переписывается пункт 1; на Fly Sprites пропадает и пункт 2.

**Первый тест облака:** работает ли `codex login --device-auth` в контейнере без браузера и переживает ли вход упаковку в tar и восстановление.

### Цены (отчёт внешнего агента, по прайсингам, без реальных запусков)

Обычный сценарий — 2 часа в день, ~1 GiB RAM:

| Провайдер | На пользователя в месяц | Хранение во сне |
|---|---|---|
| Cloudflare Containers (basic) | ~$0,8 + $5 Workers Paid на аккаунт | снимки в бете, 30 дней; поэтому свой бэкап в R2 |
| Fly Sprites | ~$1,7 | постоянный диск, пробуждение по HTTP < 1 с |
| Fly Machines | ~$1,2 | том, оплачивается во сне |
| Beam VM / boat.dev | ~$1–1,1, но минимум $20 на аккаунт | диск сохраняется; у boat.dev гарантия 14 дней |
| Freestyle Free | $0 в пределах лимитов | подходит для бесплатного теста цикла сна |

Облако обходится примерно в $1–2 на пользователя — меньше подписки $10. Выбор определяет надёжность хранения, а не цена.

## Как управлять harness (15 ноября)

- **Как в T3 Code.** Долгоживущий процесс `claude --input-format stream-json --output-format stream-json --resume <id>` или `codex app-server` (JSON-RPC). Сообщения идут в stdin, события читаются из stdout. Модель меняется перезапуском с тем же `--resume`. Свои инструменты (поручить задачу, память) даём через MCP. Цикл агента остаётся у harness — это нативное использование подписки.
- **Pi.** Подключается так же через `pi --mode rpc`, но не в фазе 1. Harness в программе — сменный модуль с интерфейсом «отправить сообщение → поток событий».
- **Подписка Claude внутри Pi (`pi-claude-code`)** — не используем для продукта. Цикл ведёт Pi, а Claude Code служит только трубой к модели. По запросам это отличимо от обычного Claude Code (`--max-turns 1`, фиктивные MCP-инструменты, повтор истории), поэтому Anthropic может банить аккаунты, не ломая T3. Для личного эксперимента — на свой риск.
