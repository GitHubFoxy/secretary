# 0006. Процессами harness управляют группы процессов и systemd

Статус: принято 19 ноября 2026 года (PR #36).

## Контекст

Агент может запустить долгие инструменты: сборки, серверы, браузеры. Их нужно останавливать вместе с агентом, а после падения Secretary — не оставлять сиротами. Раньше это решалось вручную: обход `/proc`, идентификаторы процессов в базе, запрет удаления сессий, которые когда-либо запускались. Это была самая большая и хрупкая часть `Session`.

## Решение

- Harness запускается через `setsid` и становится лидером своей группы процессов. Остановка — один `SIGKILL` всей группе.
- Если падает сам Secretary, всё, что осталось, убивает systemd: `secretary.service` использует `KillMode=control-group`.
- Удалить можно любую остановленную Session.

## Последствия

- Код отслеживания процессов и его тесты удалены.
- Запуск без systemd (например, `bun run start` вручную) не защищён от сирот после падения.
- Инструмент, который сам вызывает `setsid`, уходит из группы, и остановка Session его не убьёт. Его всё равно убьёт systemd при остановке службы.
