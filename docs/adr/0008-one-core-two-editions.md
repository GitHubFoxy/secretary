# 0008. Одно ядро, две редакции: сначала для разработчиков, потом для всех

Статус: принято 17 октября 2026 года для прошлой версии на Go (её ADR 0004), перенесено 19 ноября 2026 года.

## Контекст

Первые пользователи — разработчики, которые уже платят за Claude Code или Codex и умеют держать свой сервер. Конечная цель — платный личный помощник для людей, у которых нет ни подписки, ни сервера и которые не хотят разбираться в harness. Этим аудиториям нужна разная подготовка окружения, но один и тот же продукт: разговор с Secretary Agent, Specialists, история, телефон.

## Решение

1. **Одно ядро.** Обе редакции — одна программа Secretary. Разговор, Session, делегирование и клиент одинаковые.
2. **Developer Edition — сейчас.** Свой Host, один владелец, свой вход в Claude Code или Codex (достаточно одного). Без облачного аккаунта Secretary.
3. **Hosted Edition — потом.** Пользователь платит за готового помощника. Продавец даёт окружение (контейнер на пользователя) и, при необходимости, inference. Пользователь не видит ни CLI harness, ни серверов.
4. Мультипользовательский вход, изоляция, оплата и выдача контейнеров — задачи Hosted Edition. Они не блокируют Developer Edition.
5. Не объединяем и не перепродаём личные подписки пользователей для обслуживания других людей. Источник inference для Hosted Edition выбирается отдельно и законным путём (см. [ADR 0005](0005-native-harness-on-user-subscription.md)).

## Последствия

- Developer Edition можно выпускать раньше: она проверяет ценность продукта на людях, которым не нужна помощь с установкой.
- Деньги приходят из Hosted Edition и того, что вокруг неё: окружение, inference, подписка, реферальные предложения (#15), а не из продажи самой программы.
- Всё, что сейчас предполагает одного владельца (адрес сервера в Android-приложении, вход по коду сопряжения, MCP без авторизации), нужно явно пересмотреть перед Hosted Edition.
