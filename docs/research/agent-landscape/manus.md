# Manus: продуктовый отчёт

**Проверено:** 2026-10-07. **Уверенность:** высокая по функциям, тарифам и истории компании (официальные docs, help center, CNBC/BBC/AP), средняя по внутреннему устройству агентов, низкая по надёжности долгих задач и восстановлению после сбоев. Продукт не устанавливался и не тестировался.

## 1. Краткое резюме

Manus — облачный general-purpose агент от Butterfly Effect (те же люди, что Monica.im; основаны в Китае, переехали в Сингапур). Пользователь описывает задачу словами, агент планирует, выполняет на своих виртуальных компьютерах и возвращает готовый артефакт: отчёт, сайт, слайды, таблицу. Два режима: Chat для быстрых вопросов и Agent для автономной работы. Отдельный новый продукт Cue (сентябрь 2026) — персональные агенты с телефоном, почтой, кошельком и своим компьютером.

Запуск — начало 2025 года. Компания заявила $100M ARR за 8 месяцев после запуска и run rate выше $125M, обработано 147T токенов, создано 80M+ виртуальных компьютеров. Это заявления компании. Meta объявила о покупке примерно за $2B в декабре 2025, Китай заблокировал сделку в апреле 2026, с августа 2026 Manus снова независимый. [CNBC 30.12.2025](https://www.cnbc.com/2025/12/30/meta-acquires-singapore-ai-agent-firm-manus-china-butterfly-effect-monicai.html), [CNBC 11.08.2026](http://cnbc.com/2026/08/11/manus-china-meta-acquisition.html).

Для пользователя Secretary главное ограничение: Telegram, терминальный Pi-стиль UX и пользовательски управляемые persistent Workers в продукте не обнаружены. Это закрытый облачный сервис с кредитной экономикой.

## 2. Масштаб и перспективы

Публичных независимых данных об активных пользователях и удержании нет, кроме заявлений компании: миллионы пользователей и бизнесов, самый быстрый взлёт к $100M ARR в истории по их словам. Отдельного репозитория продукта нет, это не OSS. Сравнение с ChatGPT, Lovable и Replit компания ведёт сама на своих страницах, что говорит о позиционировании против coding-агентов, а не только против чат-ботов.

Независимость после срыва сделки с Meta — открытый вопрос: сильный трекшн, но и зависимость от облачных compute-мощностей и frontier-моделей.

## 3. Установка и доступ

**Платформы:** web app, desktop app (Windows и macOS), mobile app, расширение Manus Browser Operator для Chrome. Cue доступен на web, desktop и mobile, iOS на момент запуска ждал ревью App Store, вход по инвайт-коду.

**Тарифы (проверено по help center и pricing):** Free $0 (Chat + Agent Lite, 300 кредитов в день, 1 concurrent task, 2 scheduled tasks), Standard от $20/мес (4000 кредитов/мес), Customizable от $40/мес (8000 кредитов/мес, 7-day trial), Extended $200/мес (40000 кредитов/мес), Team от $20/seat/мес (shared credits, SSO, admin, audit). Годовая оплата −17%. На платных: 20 concurrent tasks, 20 scheduled tasks, доступ к моделям 2.0 Max / 2.0 / Lite. [Help: pricing](https://help.manus.im/en/articles/11711111-what-is-the-current-membership-pricing-for-manus), [Docs: plans](https://manus.im/docs/introduction/plans).

**Первые шаги:** регистрация, выбор задачи из стартовых (slides, website, games, video, design), подключение коннекторов, запуск. Отдельной установки для базового сценария нет.

Выбор базовой модели пользователю не предлагается напрямую: режимы Max / 2.0 / Lite выбираются за него. BYOK не документирован.

## 4. Первые 30 минут: реконструкция по документации

Вероятный путь: открыть web app, дать задачу вроде «каждый понедельник в 8 утра исследуй топ-5 конкурентов и пришли сводку», подключить Google Drive + Notion + Calendar через коннекторы, получить первый артефакт. Трение на старте: понимание кредитной цены задачи, настройка коннекторов, формулировка настолько конкретно, чтобы агент не жег итерации. Свои же docs советуют сначала прогнать задачу вручную и только потом ставить на расписание.

## 5. Ежедневный пользовательский опыт

- **Chat mode:** быстрые вопросы, дешево по кредитам.
- **Agent mode:** автономная задача на cloud computer; ноутбук можно закрыть, работа продолжается.
- **Модели-режимы:** 2.0 Max для глубокого, 2.0 обычный, Lite для простого. Роутер выбирает сам.
- **Projects:** persistent workspace с master instruction и knowledge base из файлов; каждая новая задача внутри наследует контекст. Безлимит по числу, приватны по умолчанию, шаринг явным инвайтом на проект и отдельно на задачу.
- **Scheduled Tasks 2.0:** расписание словами («каждую пятницу в 17:00»), выполняется внутри того же task-контекста с его файлами и историей, а не с нуля. Side panel, schedule view, calendar view, run history с переходом к результату конкретного рана. Skip confirmations для доверенных workflow. Расписания также внутрь web-приложений, собранных в Manus.
- **Wide Research:** распараллеливание исследования на множество суб-агентов со сведением в один результат.
- **Деливераблы:** 13 встроенных типов готовой работы: сайты, слайды, игры, видео, дизайн, музыка, таблицы. Результат — артефакт, а не сообщение.
- **Коммуникации:** Slack-интеграция, Mail, share-ссылки с replay, API для разработчиков.
- **Telegram, CLI, Pi-терминал:** официально не перечислены.

Анонс обещает продолжение контекста между ранами внутри задачи, но переносимая Conversation с единым порядком сообщений поперёк каналов не описана.

## 7. Делегирование и persistent workers

В базовом Manus пользователь создаёт задачи, а не исполнителей. Параллельность — через concurrent tasks и Wide Research суб-агентов, но это внутренняя параллельность одной задачи, а не адресуемые persistent Workers с Follow-up у того же исполнителя.

Ближе всего к модели Secretary — Cue: именованный агент со своей conversation и памятью, групповые чаты где агенты передают работу друг другу, пользователь задаёт направление и принимает финальное решение. Но пользовательское управление lifecycle (создать/закрыть/явно продолжить того же), статусы, биндинги и runtime-восстановление в публичных материалах не расписаны. Scheduled Tasks 2.0 с продолжением в том же контексте — это по сути Follow-up по расписанию, но без видимого исполнителя.

## 8. Контроль, безопасность и надёжность

Cue заявляет: пользователь задаёт бюджет кошелька и принимает финальные решения. Как именно approve-ятся отдельные транзакции, как ограничиваются действия агента с его email/телефоном и как ревьюить действия задним числом — анонс не раскрывает. Это главный открытый вопрос безопасности продукта.

Browser Operator работает в локальном браузере с сессиями пользователя: не нужно отдавать пароли в облако, доступ выглядит легитимным для защитных систем сайтов. Разумный компромисс, но scope видимости агента в браузере и обработка чувствительных страниц требуют отдельной проверки.

Cloud VMs не наследуют локальные логины и VPN автоматически; часть сайтов потребует отдельного входа. Про retries, восстановление рантайма после сбоя, SLA — в проверенных материалах ничего нет. Потраченные упавшим таском кредиты не возвращаются (сообщения сторонних разборов, не официальное заявление).

## 9. Стоимость

Standalone-подписки нет смысла описывать без кредитной математики:

## 10. Приватность и владение

Закрытый облачный сервис, не self-hosted и не OSS. Проекты и задачи приватны по умолчанию, шаринг только явными инвайтами. Team-план заявляет SSO, admin controls, audit logs. Политика использования данных для обучения в проверенных материалах отдельно не расписана — неизвестно. Подключённые приложения, знания проектов и артефакты привязывают к аккаунту Manus.

## 11. Проверка сценария пользователя

Сценарий: «Telegram: исследуй 3 вакансии; терминал: продолжи кодовый Task; Telegram: статус и уточнение; закрыл ноутбук; вернулся завтра».

| Этап | Что подтверждено | Что нельзя подтвердить |
|---|---|---|
| Telegram: исследовать вакансии | Агент исследует тему и вернёт артефакт; есть share-ссылки | Telegram не указан как канал; тот же контекст в мессенджере недоступен |
| Терминал: продолжить кодовый Task | Работа с репозиториями через коннектор; задача продолжается в своём контексте, включая scheduled раны | Продолжение существующей Pi CLI session и привязка к Task/Worker не документированы |
| Статус и уточнение в Telegram | Run history, side panel, уведомления; уточнение внутри той же задачи | В Telegram недоступно; адресация конкретного исполнителя не подтверждена |
| Закрыть ноутбук | Cloud computers задуманы для фоновой работы; задача переживает закрытый ноутбук | Поведение незавершённого рана при сбое облака неизвестно; кредиты за него уже списаны |
| Вернуться завтра | Та же задача, проект и контекст доступны в сервисе | Гарантий восстановления runtime, resume и доставки после сбоя нет; Worker identity и binding не описаны |

Итого: Manus закрывает «поручил и забыл, утром забрал артефакт», но не подтверждает Telegram + CLI + адресуемый persistent Worker. Для Secretary дифференциация та же, что против dots: сохранённая Personal Conversation и Follow-up к конкретному Worker как единый server-owned lifecycle.

## 12. Преимущества и слабые стороны

**По документации:** сильная сторона — полный цикл «слова → работа без присмотра → готовый артефакт» плюс Projects с наследуемым контекстом и Scheduled 2.0 внутри того же контекста. Browser Operator — самое элегантное в индустрии решение проблемы чужих логинов. Слабые стороны: кредитный счётчик на каждом шаге, закрытость, отсутствие Telegram/CLI, туман вокруг approve-транзакций в Cue.

**Внешние свидетельства:** Cue в Google Play — 4.4, 386 отзывов на конец сентября 2026; рядом с хвалебными есть жалобы на зависания на логине и краши на инвайт-коде в первые дни. Единичные отчёты, не оценка надёжности. Один из ревьюеров прямо просит привязать Cue к той же подписке Manus — симптом усталости от подписочного стека.

## 13. Выводы для Secretary

1. **Browser Operator копировать первым.** Агент в браузере пользователя вместо облачной виртуалки с его паролями: дешевле, честнее, меньше проблем с безопасностью. Для Secretary это новый тип Execution environment на Node.
2. **Wide Research = fan-out/fan-in Workers.** Пачка Workers на одну цель со сведением в один Result. Worker-модель Secretary это умеет из коробки, нужен только оркестратор сведения.
3. **Scheduled внутри того же контекста.** Manus 2.0 подтверждает ставку: расписание продолжает задачу, а не стартует пустую. Для Secretary это Follow-up по расписанию тому же `worker_ref`.
4. **Projects как master instruction + knowledge base.** У Secretary Projects сейчас это mappings и policy pins; добавить наследуемые инструкции и файлы проекта.
5. **Деливераблы как артефакты Result.** Result уже поддерживает artifact references — докрутить рендер, а не возвращать текст.
6. **Не копировать кредитную экономику.** Это то, чем Secretary бьёт: работа на уже оплаченных ключах без счётчика за ран.
7. **Урок Manus для позиционирования:** люди платят ещё одну подписку, когда агент делает работу без них ($100M за 8 месяцев). Подписка сама по себе не барьер, барьер — невнятная ценность. Продавать надо «утром забрал готовое», а не «любую модель».

Это продуктовые гипотезы, не утверждение о существующих возможностях Secretary и не готовые задания.

## 14. Открытые вопросы и hands-on план

Неизвестно: точная цена кредитов по типам задач и возврат за фейлы; scope видимости Browser Operator; механизм approve отдельных платежей в Cue; поведение ранов при сбоях облака; переносимость истории и экспорт; использование данных для обучения.

Будущий тест на Free без чувствительных данных: задача-исследование с деливераблом, Wide Research, Project с master instruction, scheduled задача с проверкой продолжения контекста, Browser Operator на тестовом сайте, замер кредитов до/после, удаление данных. Записать реальные лимиты и время.
