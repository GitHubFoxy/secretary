# OpenAI dots: продуктовый отчёт

**Проверено:** 2026-10-02. **Уверенность:** высокая по опубликованным функциям и правилам доступа, средняя по тому, как обещанный общий контекст ведёт себя между каналами, низкая по устойчивости длительных задач и восстановлению сессий. Я изучал документацию и публичные свидетельства, продукт не устанавливал и не тестировал.

## 1. Краткое резюме

OpenAI dots сейчас представляет собой постоянного персонального агента внутри ChatGPT, а не отдельную локальную CLI-программу. Пользователь создаёт одного основного dot, задаёт ему цели и разрешённые действия, подключает приложения, затем пишет ему в ChatGPT или поддерживаемых каналах. У dot есть собственный cloud computer; он может продолжать работу между обращениями и вести несколько задач параллельно. OpenAI описывает это как постоянно доступного помощника. Это продуктовая формулировка, не обещание SLA.

Запуск состоялся 29 сентября 2026 года. Доступ разворачивается постепенно: Pro доступен не в EEA, Швейцарии и Великобритании; Business Premium доступен в поддерживаемых регионах; Enterprise, Edu и Healthcare могут включить beta через администратора, по умолчанию она выключена. Документация предупреждает, что функции могут ещё не появиться в конкретной учётной записи. [Анонс OpenAI](https://openai.com/index/introducing-dots/), [Getting started](https://help.openai.com/en/articles/20001530-getting-started-with-your-dot).

Лучше всего продукт подходит подписчикам ChatGPT, которым нужен фоновой помощник для деловой переписки, исследований и задач в подключённых приложениях. Для пользователя Secretary важное ограничение: Telegram, терминал Pi и пользовательски управляемые persistent Workers в документированном продукте не обнаружены.

## 2. Масштаб и перспективы

Это новый коммерческий продукт, поэтому публичных данных об активных пользователях dots, удержании и выполненных задачах пока нет. OpenAI сообщил на DevDay, что у ChatGPT 1,2 млрд пользователей в неделю; эта цифра относится к материнской платформе, не к dots, и является заявлением компании. [DevDay 2026 recap](https://openai.com/index/devday-2026-recap/).

В публичном Hacker News обсуждении анонс получил около 475 очков и 357 комментариев в снимке за день анонса. Это показатель внимания технической аудитории, не использования или удовлетворённости. Продукт закрытый: отдельного репозитория dots и применимых GitHub stars не найдено. [Обсуждение HN](https://news.ycombinator.com/item?id=49896604).

## 3. Установка и доступ

**Платформы:** создание dot доступно в ChatGPT на desktop web или в приложении ChatGPT для компьютера. Существующий dot можно использовать в мобильном приложении ChatGPT, когда доступ включён. Создать его на телефоне пока нельзя; мобильный web не поддерживается. В desktop-документации отдельно упомянуто приложение для Windows. Telegram и CLI среди каналов не указаны.

**Первые шаги по официальной инструкции:**

1. Получить подходящую подписку и дождаться включения функции в аккаунте.
2. Открыть ChatGPT desktop или desktop web и пройти onboarding. Установочной команды или отдельного инсталлятора dots нет.
3. Назвать dot, выбрать оформление; позднее имя и аватар меняются в профиле.
4. Подключить нужные приложения в `Customize → Plugins`, изучить permissions. Для Slack или texting настройка выполняется с desktop. В Slack подключение может требовать одобрения владельца workspace.
5. Определить задачу, передать детали и при необходимости приложить файл или фото кнопкой `+`.
6. При необходимости подключить локальный компьютер отдельно и явно разрешить доступ. Для Codex cloud task сначала создать environment в Codex.

Первый dot входит в Pro или Business Premium без отдельной доплаты, но требуется соответствующая подписка. Business pricing указывает Premium seat за $100 в месяц при годовой оплате или $125 при помесячной оплате в США; региональная цена может отличаться. Enterprise имеет индивидуальную цену. [Business pricing](https://openai.com/business/chatgpt-pricing/). Для самого dot опубликована allowance на более глубокую работу, а в первый месяц после запуска лимиты расширены. Количественные лимиты и детальная тарификация работы dot в проверенных материалах не расписаны.

Выбор модели пользователю не документирован: Help Center называет GPT-6 Astra. BYOK и отдельный тариф за API не описаны. До первого полезного результата нужны аккаунт/подписка, доступ к rollout и хотя бы запрос с контекстом; коннекторы нужны только для работы с внешними данными. Оценки времени до результата в источниках нет.

## 4. Первые 30 минут: реконструкция по документации

Это не hands-on тест. Вероятный короткий путь: создать dot в desktop ChatGPT, дать имя и инструкцию, затем попросить: «Проверь мой календарь на завтра и подготовь краткий список встреч, конфликтов по времени и вопросов, к которым стоит подготовиться». Если календарь не подключён, добавить соответствующий plugin и подтвердить его права. После ответа открыть профиль dot и посмотреть `In progress`, `Scheduled` или `Completed`; можно открыть cloud computer, чтобы осмотреть и продолжить работу.

Трение на старте: rollout, подписка и отдельное подключение приложений. Локальный компьютер должен оставаться онлайн с открытым ChatGPT. Время настройки источники не указывают.

## 5. Ежедневный пользовательский опыт

- **ChatGPT:** основной интерфейс для создания и общения; на desktop есть профиль dot и список активностей. Mobile app позволяет обращаться к уже созданному dot и показывает управление его компьютером.
- **Slack и Microsoft Teams:** поддерживаются как messaging integrations там, где доступны. Enterprise admin может отдельно разрешить добавление dots. Slack или Teams workspace и permissions подключаются отдельно.
- **Texting:** ограниченная beta через стороннего провайдера; по опубликованному Help Center она доступна лишь части Pro-пользователей в США и недоступна Business/Enterprise. Чувствительные сведения через SMS OpenAI советует не передавать.
- **Голос:** OpenAI обещает звонки dot через ChatGPT. Нет подтверждения, что voice одинаково работает в Slack, Teams или texting.
- **Telegram, web-чат вне ChatGPT, терминал:** официально не перечислены.

Анонс обещает, что dot сохраняет полный контекст при обращении из разных каналов. Help Center подтверждает одну dot identity и настройку каналов, но отдельно не гарантирует единый транскрипт или одинаковую историю сообщений в каждом канале. Это различие важно: общий контекст заявлен, переносимая Conversation с однозначным порядком сообщений не описана.

Файлы и фото прикрепляются к разговору; пользователь может уточнять запрос. Dot показывает `In progress / Scheduled / Completed`, но документация не описывает универсальные pause/cancel/resume или live-log для каждой задачи. [Getting started](https://help.openai.com/en/articles/20001530-getting-started-with-your-dot).

## 7. Делегирование и persistent workers

В публичном продукте пользователь создаёт dot, а не отдельного Worker под каждую задачу. Dot имеет постоянное имя и собственный cloud computer; получает новые задачи и, по словам OpenAI, может работать над несколькими проектами. В профиле видны отдельные активности и их статусы. Это не то же самое, что persistent Worker identity, закреплённая за одной Task, возможность адресовать именно этого Worker и продолжать его Task.

Публичная документация не описывает пользовательские роли субагентов, параллельный выбор исполнителей, создание/закрытие Workers или выбор existing Worker для Follow-up. OpenAI говорит о будущих командах dots и показывает preview specialist dots для организаций, но не утверждает, что индивидуальный пользователь сейчас распределяет задачи между ними. Возможный внутренний multi-agent pipeline не равен пользовательскому управлению Workers.

В каналах пользователь взаимодействует с dot; не документировано, что можно обратиться из Slack к отдельной длительной задаче или открыть runtime session конкретного исполнителя. Допущение пользователя об Hermes проверено только в рамках отдельного исследования; в этом отчёте нельзя делать вывод о наличии или отсутствии субагентов в Hermes. По dots ответ проще: публично управляемые persistent Workers не подтверждены.

## 8. Контроль, безопасность и надёжность

По умолчанию действия разделяются на требующие подтверждения, заранее разрешённые и выполняемые без вопроса. Custom Rules позволяют задавать дополнительные границы, например не отправлять email, но не могут отключить встроенные safeguards. Plugin permissions задаются отдельно; администратор Enterprise управляет доступом к dots, local computer, cloud browser/network/computer и password manager. В Enterprise доступ dots и локальная машина по умолчанию выключены.

Cloud computer не наследует автоматически VPN, локальные входы браузера или device policies; сайт может потребовать отдельного входа. Доступ к локальной машине требует включённого разрешения, онлайн-компьютера и открытого приложения. Отключение приложения не удаляет уже полученные dot сведения; удаление самого dot удаляет его контекст. Доступ dot к этим данным следует рассматривать как самостоятельное предоставление полномочий, а не как безопасное продолжение личного браузера. [Privacy, security, and safety FAQ](https://help.openai.com/en/articles/20001529-dots-privacy-security-and-safety-faqs), [workspace controls](https://help.openai.com/en/articles/20001554-manage-dots-in-chatgpt-workspaces).

Для Personal ChatGPT обучение на содержимом dot регулирует `Improve the model for everyone`; Business, Enterprise и Edu по умолчанию не используют данные для обучения. Не описаны retries, восстановление cloud runtime после перезапуска, SLA или журнал расходов. «Always-on» на эти вопросы не отвечает.

## 9. Стоимость

Standalone тарифа нет: нужен Pro или Business Premium, а первый dot включён в подписку. Для Business Premium публичная цена США $100/месяц при годовой оплате и $125/месяц при помесячной оплате. Enterprise тарифицируется индивидуально. OpenAI говорит об allowance на глубокую работу и временно увеличенном лимите в первый месяц, но числовой лимит, счётчик задач, стоимость ускорения, перерасход и отдельную цену compute в проверенных источниках не указал. Тариф Pro зависит от конкретного плана и рынка; точную локальную сумму нужно смотреть на странице [ChatGPT pricing](https://chatgpt.com/pricing/). BYOK не документирован.

## 10. Приватность и владение

Это закрытый облачный сервис OpenAI, не self-hosted и не OSS. Контекст dot хранится, пока dot существует; его удаление не удаляет данные из ChatGPT Memory. Отдельные dot memories нельзя поштучно просматривать, удалять или менять. Экспорт и переносимость dot history не описаны.

Business-план заявляет отсутствие обучения на рабочих данных по умолчанию; Enterprise добавляет отдельные меры хранения и корпоративные контроли. Это общие свойства планов, не самостоятельная техническая спецификация изоляции cloud computer dots. Подключённые приложения, память и рабочие артефакты привязывают пользователя к аккаунту OpenAI и его plugin-интеграциям.

## 11. Проверка сценария пользователя

Сценарий: «Telegram: исследуй 3 вакансии; терминал: продолжи кодовый Task; Telegram: статус и уточнение; закрыл ноутбук; вернулся завтра».

| Этап | Что подтверждено | Что нельзя подтвердить |
|---|---|---|
| Telegram: исследовать вакансии | Dot умеет исследовать тему; приложения можно подключить, задачи вести в ChatGPT, Slack или доступном texting. | Telegram не указан. Нельзя считать, что бот там существует или что Telegram-вход добавится в тот же контекст. |
| Терминал: продолжить кодовый Task | Dot может создать Codex/Work task на подключённом компьютере или работать с заранее созданным Codex cloud environment. | Прямое продолжение текущей Pi CLI session и привязка к существующей Task не документированы. Локальный доступ требует работающий компьютер и ChatGPT app. |
| Запросить статус и уточнить в Telegram | Статусы dot видны в профиле ChatGPT; анонс обещает общий контекст каналов. | В Telegram это недоступно; единый порядок Conversation entries и адресация конкретного Worker не подтверждены. |
| Закрыть ноутбук | Cloud computer задуман для фоновой работы; общение и прогресс продолжаются между сессиями. | Локальная работа не должна считаться доступной после выключения ноутбука: локальный computer должен оставаться онлайн, а приложение открытым. Поведение незавершённого cloud task при сбое неизвестно. |
| Вернуться завтра | Тот же dot и его контекст должны быть доступны в сервисе, пока dot существует. | Гарантии восстановления runtime session, повторного запуска и доставки результата после сетевого/серверного сбоя нет. Worker identity и Task binding в модели продукта не описаны. |

Итого: dots закрывает часть идеи «один помощник в нескольких каналах», но не подтверждает нужные пользователю Telegram + Pi CLI + Worker binding. Для Secretary отличием может стать именно сохранённая Personal Conversation и Follow-up к persistent Worker, если они будут реализованы как единый server-owned lifecycle, а не просто заявлены как общий контекст.

## 12. Преимущества и слабые стороны

**По документации:** сильная сторона dots в том, что у одного именованного помощника есть отдельный cloud computer, app permissions и desktop/mobile интерфейс со статусами. Можно продолжить разговор и делегировать работу без ручного запуска локального процесса. Слабые стороны для опытного пользователя: закрытая среда, зависимость от подписки и rollout, отсутствие Telegram/CLI и недостаточно точные гарантии контроля длительной задачи.

**Внешние свидетельства, не проверенные OpenAI:** в первые дни появились Codex issues о продолжении локальных диалогов и доступности локального компьютера. Один сообщает об успешной проверке, другой о проблемах обнаружения/маршрутизации. Это единичные отчёты, не оценка частоты ошибок. [Codex issue #49482](https://github.com/openai/codex/issues/49482), [Codex issue #49626](https://github.com/openai/codex/issues/49626).

## 13. Выводы для Secretary

1. **Сделать продолжение работы видимым.** Списки активных, запланированных и завершённых задач проще, чем поиск по длинной переписке. Для Secretary важно показывать Task и текущий Worker binding в Personal Conversation.
2. **Свести доступ к компьютеру и разрешениям в явные controls.** Dots отделяет cloud computer, local computer, plugins, browser и password manager. Такое разделение понятнее, чем одно неопределённое «агенту можно всё».
3. **Не подменять общий контекст идентичностью исполнителя.** Один dot удобен для пользователя, но для длительной делегации нужен способ увидеть, какая Task закреплена за каким Worker, и адресовать Follow-up именно этому Worker.
4. **Каналы и runtime должны переживать закрытый ноутбук.** Dots даёт cloud runtime, но local work зависит от включённого компьютера. Возможная дифференциация Secretary: раздельно показывать состояние server-side Conversation/Task/Worker binding и доступность Execution node, без обещания, что локальный runtime всё ещё работает.

Это продуктовые гипотезы, не утверждение о уже существующих возможностях Secretary и не готовые задания на реализацию.

## 14. Открытые вопросы и hands-on план

Неизвестно, объединяются ли сообщения каналов в один видимый транскрипт, как точно устроены cancel/resume и retries, как dot восстанавливает незавершённый cloud task, сколько глубоких задач входит в allowance, можно ли передать ему существующую Pi или Codex session, и как экспортировать весь dot context.

Будущий тест на Pro без чувствительных данных: создать dot в desktop web, подключить тестовый Slack, проверить сообщение и голос в ChatGPT, запустить исследование параллельно с Codex task и запросить уточнение из другого канала. Затем проверить облачную и локальную работу при выключенном компьютере, cancel/resume, удаление dot, Memory и доступы приложений. Записать реальные лимиты и время, не обобщая их на другие рынки.
