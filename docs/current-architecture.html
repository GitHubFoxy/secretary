Приватный сервер.
Ни одного открытого порта.

Tailscale даёт доверенным устройствам приватный HTTPS-доступ к серверу. Telegram работает отдельно: сервер сам подключается к Bot API и забирает сообщения через long polling.

01

Карта системы

приватный HTTP / WebSocket в tailnet исходящий Telegram Bot API Dispatch к Worker durable state / Result
Публичного маршрута Telegram → omarchy сейчас нет. Сервер открывает HTTPS-соединение к Telegram сам и получает обновления в ответ на long-poll запрос.
02

Что происходит с сообщением

Канал

Owner пишет в General. Telegram хранит сообщение и выдаёт его следующему `getUpdates` запросу бота.

PHONE → TELEGRAM

Secretary server

Адаптер проверяет чат и автора, передаёт текст локальному API. Server сохраняет Conversation entry и создаёт turn.

TELEGRAM → LOOPBACK

Исполнение

Secretary отвечает сам или вызывает lifecycle tool. Для работы он создаёт Worker и отправляет Dispatch на Node.

SECRETARY → NODE → WORKER

Ответ

Server сохраняет terminal Result. Важные Worker events и результат зеркалятся в General и его Worker Topic.

RESULT → SQLITE → TELEGRAM
03

Зачем здесь Tailscale

Что он делает

Даёт приватный путь до сервера

  • Owner browser и paired Clients входят в tailnet с доверенных устройств.
  • Tailscale Serve принимает приватный HTTPS и проксирует его на `127.0.0.1:8081`.
  • ACL ограничивает доступ по identity и устройствам.
  • WireGuard соединяет устройства напрямую, если возможно; иначе трафик идёт через DERP relay, оставаясь шифрованным.
Чего он не делает

Не принимает сообщения Telegram

  • Telegram не состоит в tailnet и не может вызвать приватный Tailscale Serve адрес.
  • Поэтому бот использует исходящий long polling, а не webhook.
  • Для webhook понадобится отдельный публичный HTTPS вход, например Funnel или relay. Нельзя просто опубликовать весь `secretaryd`.
  • Tailscale не запускает Workers и не хранит Conversation. Это только сетевой доступ.
04

Где появляется задержка

Входящее сообщение уже не ждёт минуту между запросами. При включённом long poll Telegram может ответить сразу, а после ответа сервер начинает следующий запрос без дополнительной паузы.

getUpdates
timeout ≤ 2 s
Secretary / Worker
время модели
event bridge
опрос раз в 100 ms
sendMessage
flush ≤ 2 s

Две секунды ограничивают ожидание входящего update на границе двух poll запросов. Генерация ответа зависит от модели и работы Worker. После завершения turn текущая пакетная отправка может добавить до двух секунд.

Webhook позже

Webhook уберёт ожидание следующего poll. Для него нужен изолированный receiver, публичный HTTPS маршрут, secret header и durable inbox с дедупликацией. Tailscale Serve сам по себе не подходит, потому что доступен только tailnet.

06

Слои и source of truth

01 / Channel

Telegram adapter

Только транспорт: принимает updates, проверяет allowlist, маршрутизирует General и Worker Topics. Он не владеет Conversation или Worker lifecycle.

02 / Product server

secretaryd

Хранит durable Conversation и Worker state, строит контекст, запускает Secretary turn и выдаёт lifecycle tools. API доступен локально и через приватный Serve.

03 / Execution

secretary-node

Отдельный systemd service. Node сам устанавливает канал к server, запускает Worker в workspace и возвращает события и terminal Result.

04 / Storage

SQLite и локальные профили

SQLite в `~/.local/share/secretary/secretary.db` хранит durable state. `config.toml`, `profiles/*.md` и `user.md` задают конфигурацию и инструкции.
