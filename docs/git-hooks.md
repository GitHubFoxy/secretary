# Подключить проверку размера файлов перед коммитом

Из корня репозитория выполните:

```sh
git config core.hooksPath .githooks
```

Для хука нужны Git и Python 3. Настройка действует в текущем локальном репозитории; после нового клонирования повторите команду.

При `git commit` хук проверяет полное содержимое добавленных, изменённых и переименованных файлов с расширениями `.go`, `.sh` и `.svelte` из index. Остальные типы файлов пропускаются. Лимит — 5 000 токенов, где число токенов равно числу байт, делённому на 4. Файл размером ровно 20 000 байт проходит проверку. Изменения вне index и удаления не проверяются. Символические ссылки и подмодули пропускаются.

Происхождение файла от агента или человека нельзя надёжно определить через Git. Среди `.go`, `.sh` и `.svelte` исключены:

- Файлы с атрибутом `linguist-generated=true` или `linguist-generated` в staged-версии `.gitattributes`.
- Файлы с маркером `Code generated … DO NOT EDIT` или `@generated` в первых 4 096 байтах.

Lockfile и `go.sum` не входят в проверяемые расширения.

Для нового результата генерации добавьте точный путь в `.gitattributes` с `linguist-generated=true` и выполните `git add .gitattributes`. Не исключайте написанный вручную исходный код. Для слишком большого исходного файла хук выводит размер и инструкции по разделению кода, тестов и документации.

Запустить интеграционные проверки хука:

```sh
python3 scripts/pre-commit-test.py
```
